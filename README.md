## О проекте

**Xmenu** — интерактивный POSIX shell-скрипт для управления сетевыми компонентами на роутерах **Keenetic / Netcraze** с установленным **Entware**. Он запускается из SSH и объединяет установщики, готовые профили XKeen, операции со стратегиями NFQWS/NFQWS2 и базовую диагностику.

Xmenu — это оболочка управления, а не отдельный DPI-движок, VPN-протокол или замена интерфейса KeeneticOS. Установка компонентов выполняется только после выбора соответствующего пункта меню. При первом запуске меню открывается сразу; автоматическая установка всех пакетов не запускается.

> [!WARNING]
> Часть действий загружает и запускает сторонние установщики с правами `root`, меняет пакеты, конфигурации или службы. Проверь источник, сохрани важные конфиги и убедись, что у тебя есть способ восстановить доступ к роутеру.

## Возможности

- **XKeen:** Stable, две разновидности XKeen UI и готовые профили с Xray или Mihomo.
- **NFQWS / NFQWS2:** установка компонентов, выбор стратегии, проверка файлов стратегии и загрузка blobs/lists.
- **`rkn.list`:** запуск штатного действия обновления списка из `nfqws-menu`.
- **Сетевые утилиты:** DPI Detector, TG WS Proxy Rust, KeenKit и awg-manager.
- **Статус:** модель роутера, KeeneticOS, архитектура Entware, обнаруженные пакеты и версии.
- **Управление:** цифровое меню удаления, подтверждения опасных действий и выбор языка RU/EN.
- **Обновление Xmenu:** пункт `23` скачивает скрипт из собственного GitHub-репозитория, проверяет его и только затем заменяет текущую версию.

## Требования

1. Keenetic / Netcraze с установленным Entware.
2. SSH-доступ к shell Entware от имени `root`.
3. Работающий `opkg` и доступ к репозиториям Entware.
4. Интернет-доступ к GitHub или доступным зеркалам загрузки.
5. Свободное место в `/opt` для выбранных пакетов и файлов.

Скрипт рассчитан на POSIX `sh` и BusyBox `ash`. В зависимости от операции могут понадобиться `curl` или `wget` с HTTPS, `ca-certificates`, `jq`, `gawk`, `bash`, `coreutils-sha256sum` и другие пакеты Entware. Xmenu пытается проверить и подготовить необходимые инструменты при выполнении сетевых операций.

## Установка

Подключись по SSH к роутеру и вставь **одну команду целиком**. Она обновит индексы Entware, установит транспортные пакеты, скачает скрипт, проверит синтаксис, сохранит предыдущую версию и откроет меню.

```sh
opkg update && opkg install curl libnghttp2 ca-certificates && curl -fLsS --retry 3 -o /tmp/xmenu-v1.0.sh https://raw.githubusercontent.com/RaNgeRwWs/Xmenu/main/xmenu-v1.0.sh && sh -n /tmp/xmenu-v1.0.sh && busybox ash -n /tmp/xmenu-v1.0.sh && mkdir -p /opt/bin /opt/etc/xkeen-menu/backups && { if [ -f /opt/bin/xmenu ]; then cp -p /opt/bin/xmenu "/opt/etc/xkeen-menu/backups/xmenu-before-$(date +%Y%m%d-%H%M%S).sh" || exit 1; fi; } && cp /tmp/xmenu-v1.0.sh /opt/bin/xmenu && chmod 700 /opt/bin/xmenu && exec /opt/bin/xmenu
```

Если команда прервалась на загрузке или проверке, существующий `/opt/bin/xmenu` не заменяется. Если на роутере отсутствует команда `busybox`, сначала проверь доступность BusyBox и Entware; не убирай проверку без причины.

### Запуск после установки

```sh
xmenu
```

Если команда `xmenu` не находится в `PATH`, используй полный путь:

```sh
/opt/bin/xmenu
```

## Информация об устройстве

### Модель и KeeneticOS

Xmenu запрашивает версию через локальный Keenetic RCI API:

```text
http://127.0.0.1:79/rci/show/version
```

Если API не отдаёт необходимые сведения, скрипт использует резервные источники, включая `ndmc`, `/proc/device-tree/model` и `/proc/device-tree/compatible`. Если модель или версия не определились, в меню будет показано соответствующее сообщение вместо догадки.

### Архитектура Entware

Порядок определения архитектуры:

1. `opkg print-architecture` — основной источник.
2. `/opt/etc/opkg.conf` — запасной источник.
3. `uname -m` — последний запасной вариант.

Xmenu нормализует известные значения, в частности `aarch64`, `mipsel`, `mips`, `x86_64` и `x86`. Для установки пакетов важна архитектура Entware, а не только аппаратное описание процессора.

### Установленные компоненты

Список строится по данным `opkg`, исполняемым файлам, init-скриптам и файлам версий. Отсутствующие компоненты не выводятся как установленные. В некоторых случаях версию бинарника или внешней панели получить невозможно; надпись «версия неизвестна» не означает, что компонент обязательно сломан.

## Стратегии NFQWS

### Пункт 11 — выбрать и применить стратегию

Xmenu использует стратегические файлы из репозитория и кэша `nfqws-menu`. Доступные названия выводятся в меню, после выбора пользователь подтверждает применение.

В общем случае операция:

1. Проверяет наличие выбранной стратегии.
2. Подготавливает временную конфигурацию.
3. Сохраняет важные параметры текущего конфига, включая `ISP_INTERFACE`, если они присутствуют.
4. Переносит подключение `rkn.list` в новый `MODE_LIST`, если список был подключён ранее.
5. Проверяет и получает требуемые blobs/lists.
6. Создаёт резервную копию заменяемой конфигурации.
7. Применяет выбранный файл и пытается перезапустить соответствующую службу.

Основные файлы конфигурации:

| Движок | Конфигурация | Init-скрипт (если установлен) |
|---|---|---|
| NFQWS v1 | `/opt/etc/nfqws/nfqws.conf` | `/opt/etc/init.d/S51nfqws` |
| NFQWS2 | `/opt/etc/nfqws2/nfqws2.conf` | `/opt/etc/init.d/S51nfqws2` |

Не выбирай новую стратегию, если не хочешь заменить текущий конфиг. Перед применением убедись, что нужная стратегия подходит твоей сети и провайдеру.

### Пункт 12 — защита кастомной конфигурации

Проверка и синхронизация blobs/lists не должны заменять произвольно изменённый конфиг только из-за старого маркера выбранной стратегии. Xmenu сравнивает активную конфигурацию с сохранённым оригиналом стратегии; автоматическое обновление допускается только тогда, когда исходный конфиг совпадал с соответствующей стратегией. Комментарии, пустые строки и некоторые служебные отличия при сравнении могут не учитываться.

Если активный конфиг отличается от исходной стратегии, Xmenu должен оставить его без автоматической подмены. Для намеренного перехода на другую стратегию используй пункт `11`.

## Blobs, lists и rkn.list

### Пункт 12 — blobs и lists активного конфига

Xmenu извлекает пути к blobs (`.bin`) и спискам (`.list`) из активного конфига. Если предусмотрен манифест SHA-256, файлы сверяются с ним; совпадающие файлы не требуется скачивать заново. Перед заменой существующего файла скрипт пытается сохранить резервную копию. Симлинки и подозрительные пути не должны автоматически перезаписываться.

### Пункт 13 — установить необходимые blobs

Целевой каталог NFQWS2:

```text
/opt/etc/nfqws2/blobs
```

Операция получает манифест, проверяет записи и контрольные суммы и скачивает недостающие или отличающиеся файлы. Результат зависит от доступности источника, корректности манифеста и места на файловой системе.

### Пункт 14 — обновить rkn.list

Пункт делегирует операцию `update_rkn_list` актуальному скрипту `nfqws-menu`. Доступные действия и сообщения могут меняться вместе с upstream-проектом.

Типичные пути списка:

| Движок | Путь `rkn.list` |
|---|---|
| NFQWS v1 | `/opt/etc/nfqws/rkn.list` |
| NFQWS2 | `/opt/etc/nfqws2/lists/rkn.list` |

Убедись, что установлен нужный NFQWS-движок, файл списка загрузился и активная стратегия действительно подключает список через `MODE_LIST`/`--hostlist`.

## Профили XKeen

### XKeen Stable

Пункт `1` вызывает установщик XKeen Stable. Xmenu скачивает установщик во временный файл, проверяет ключевые маркеры и shell-синтаксис перед запуском. Проверка синтаксиса не заменяет аудит кода установщика.

### XKeen UI

Пункты `2` и `3` устанавливают разные реализации интерфейса:

- `2` — XKeen UI от `zxc-rv`.
- `3` — XKeen UI от `umarcheh001`.

Перед установкой или сменой варианта UI проверь совместимость с текущей версией XKeen и используемыми конфигами.

### XKeen Auto, Mihomo и Xray

Пункты `7` и `8` настраивают XKeen Auto с выбранным ядром и GeoIPSet. Автозагрузка и ежедневное обновление GeoIP/GeoIPSet зависят от успешно установленного XKeen, `crontab` и состояния системы.

Пункты `9` и `10` запускают комбинированную установку выбранного ядра, XKeen Auto, XKeen UI, NFQWS2 и NFQWS Web. Если обязательный шаг завершился ошибкой, проверь его вывод до повторного запуска профиля. Не удаляй существующее ядро вручную, пока не убедился, что понимаешь, какие файлы используются.

## Дополнительные утилиты

### 15. DPI Detector

Установка использует проект [Runnin4ik/dpi-detector](https://github.com/Runnin4ik/dpi-detector), включая Rust-ветку. Текущая реализация в первую очередь рассчитана на `aarch64`. После установки Xmenu проверяет запуск бинарного файла; при несовместимом ELF или отсутствующем загрузчике требуется отдельная диагностика.

### 16. TG WS Proxy Rust

Управление делегируется соответствующему действию из актуального `nfqws-menu`. Если компонент предоставляет веб-панель, не открывай её порт напрямую в WAN без аутентификации, фильтрации и осознанной настройки firewall.

### 17. KeenKit

Если локальный `/opt/keenkit.sh` уже существует, Xmenu предлагает его запустить. Если файл не найден, меню предлагает установить KeenKit из upstream-источника.

### 18. awg-manager

Перед установкой проверь, что необходимый WireGuard-компонент включён и работает. Команда использует действие `menu_awg_manager` из актуального `nfqws-menu`; точные шаги зависят от текущей версии исходного проекта и пакетов Entware.

### 19. Статус и версии

Показывает сведения об устройстве, найденных компонентах, некоторых службах и активной стратегии. Если версия получена из локального файла, а не непосредственно из бинарника, это может быть сохранённое значение. При диагностике сверяй её с версией самого проекта.

### 20. Переключить язык

Пункт `20` переключает меню между русским и английским. Настройка хранится в файле:

```text
/opt/etc/xkeen-menu/language
```

Язык сообщений сторонних установщиков задаётся их авторами и может отличаться от языка Xmenu.

## Удаление компонентов

### Пункт 21 — удалить компоненты

В цифровом подменю отображаются только обнаруженные установленные компоненты. Набор вариантов зависит от пакетов, файлов и init-скриптов устройства. Удаление запрашивает подтверждение; общие зависимости и пользовательские настройки не должны удаляться без отдельного действия.

Отдельные операции доступны для пакетов NFQWS, NFQWS UI, XKeen, Xray/Mihomo, DPI Detector, awg-manager, TG WS Proxy Rust и KeenKit, если код обнаружил соответствующие компоненты. Старые установки некоторых сторонних утилит могут потребовать ручного удаления по инструкции их версии.

### Резервные файлы

В подменю есть поиск резервных файлов (`*.bak`, `*.bak.*`, `*-opkg`). Перед удалением показывается список и запрашивается подтверждение. Не очищай бэкапы сразу после обновления: сначала проверь, что компоненты запускаются и конфигурации работают.

### Пункт 22 — удалить Xmenu

Удаляется `/opt/bin/xmenu` и связанные задания cron Xmenu. Отдельное подтверждение определяет, нужно ли также удалить кэш, манифесты и резервные копии Xmenu. Эта операция не предназначена для удаления XKeen, NFQWS2 или других сетевых компонентов.

## Обновление Xmenu

**Пункт `23` — «Обновить Xmenu с GitHub»** загружает версию из:

[`xmenu-v1.0.sh` — raw.githubusercontent.com](https://raw.githubusercontent.com/RaNgeRwWs/Xmenu/main/xmenu-v1.0.sh)

Перед заменой проверяются минимальный размер файла, `#!/bin/sh`, ключевые функции, наличие самого пункта меню `23`, обработчик выбора `23`, отсутствие очевидной HTML-ошибки и результат `sh -n`. Если файл не проходит проверку, установленная версия остаётся на месте. При успешном обновлении Xmenu сохраняет предыдущую версию в каталоге резервных копий, заменяет скрипт и перезапускает меню.

Чтобы пункт `23` появился у уже установленной старой версии, сначала установи обновлённый `xmenu-v1.0.sh` из команды в разделе [Установка](#установка) или замени файл в GitHub и запусти новую версию. Самообновление не может появиться в старом скрипте, если в том скрипте ещё нет соответствующего пункта.

## Командный режим

| `xmenu install-blobs-nfqws2` | Все необходимые blobs NFQWS2 |
| `xmenu dpi-detector` | Запуск DPI Detector |
| `xmenu rkn-list` | Обработчик `rkn.list` |
| `xmenu install-tg-ws-proxy-rust` | Действие TG WS Proxy Rust |
| `xmenu install-keenkit` | Действие KeenKit |
| `xmenu install-awg-manager` | Действие awg-manager |
| `xmenu backup` | Создание архива поддерживаемых конфигураций |
| `xmenu install-all` | Сценарий установки отсутствующих компонентов |
| `xmenu install-all --yes` | Пропуск подтверждения только для предусмотренного шага NFQWS2 UI |

Некоторые команды запускают интерактивные установщики и требуют живого SSH-терминала; не используй их в cron без проверки поведения.

## Безопасность

Xmenu выполняет сторонние установщики с правами `root`. Используй только те действия и источники, которым доверяешь.

В зависимости от операции код применяет HTTPS, тайм-ауты, повторные попытки, зеркала загрузки, проверку размера и структуры, `sh -n` и SHA-256-манифесты там, где они доступны.

Важно:

- `sh -n` проверяет синтаксис, но не доказывает безопасность скрипта.
- HTTPS защищает канал передачи, но не подтверждает корректность кода автора.
- Хеш, загруженный с того же источника, не заменяет цифровую подпись издателя.
- Не все сторонние установщики имеют независимую криптографическую проверку.
- Не выставляй веб-панели компонентов напрямую в интернет без ограничений доступа.
- Перед сменой стратегии убедись, что есть резервная копия и способ восстановить рабочий конфиг.
