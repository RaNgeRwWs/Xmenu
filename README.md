## О проекте
**Xmenu** — интерактивный POSIX shell-скрипт для выполнения частых операций с сетевыми компонентами в Entware на роутерах Keenetic / Netcraze. Меню запускается локально на роутере через SSH и использует `opkg`, системные утилиты, конфиги NFQWS/XKeen и действия официального проекта `nfqws-menu`.

Xmenu помогает устанавливать компоненты по отдельности, использовать готовые профили, выбирать стратегии, проверять связанные файлы, смотреть обнаруженные версии и обновлять само меню. При обычном первом запуске Xmenu **не устанавливает все компоненты автоматически** — действия выполняются по выбору пользователя.

Xmenu не является отдельным DPI-движком, VPN-протоколом или заменой интерфейса KeeneticOS. Он служит оболочкой для локальных команд, пакетных установок и внешних установщиков.

> ⚠️ Многие действия требуют `root` и могут менять сетевые настройки, конфиги, пакеты и службы. До установки или удаления сохрани важные конфигурации и убедись, что можешь восстановить доступ к роутеру.

## Возможности
- **Компоненты:** XKeen Stable, две версии XKeen UI, NFQWS2, NFQWS Web и NFQWS UI.
- **Профили:** XKeen Auto с Mihomo или Xray, GeoIP/GeoIPSet, cron и автозагрузкой.
- **Стратегии:** список стратегий NFQWS/NFQWS2, выбор, проверка, применение и резервирование активного конфига.
- **Файлы стратегии:** получение и проверка blobs/lists, SHA-256-проверки по манифестам, полный набор blobs NFQWS2.
- **RKN:** вызов штатного действия `nfqws-menu` для обновления `rkn.list`.
- **Дополнительные утилиты:** DPI Detector, TG WS Proxy Rust, KeenKit, awg-manager.
- **Статус:** модель, версия KeeneticOS, архитектура Entware, обнаруженные компоненты и некоторые сведения о службах.
- **Удобство:** RU/EN, цифровые пункты меню удаления, подтверждения опасных операций.
- **Обновление:** скачивание новой версии Xmenu с GitHub с проверкой структуры и shell-синтаксиса перед заменой.

## Требования
1. Keenetic / Netcraze с установленным Entware.
2. SSH-доступ к shell Entware от имени `root`.
3. Рабочий `opkg` и доступ к репозиториям Entware.
4. Доступ к GitHub либо доступным зеркалам загрузки.
5. Свободное место в `/opt`, необходимое для выбранных компонентов.
6. Резервная копия важных конфигов и рабочий способ восстановить доступ.

Для сетевой загрузки необходим `curl` или `wget` с HTTPS/TLS. При необходимости Xmenu пытается установить инструменты вроде `curl`, `ca-certificates`, `wget-ssl`, `jq`, `libnghttp2`, `bash`, `gawk` и `coreutils-sha256sum`. Не каждый пакет нужен каждой функции, а доступность пакетов зависит от репозиториев и архитектуры Entware.

## Установка

Обнови индексы и установи транспортные пакеты:
```sh
opkg update && opkg install curl libnghttp2 ca-certificates
```
Скачай скрипт во временный файл:
```sh
curl -fLsS --retry 3 \
  -o /tmp/xmenu-v1.0.sh \
  https://raw.githubusercontent.com/RaNgeRwWs/Xmenu/main/xmenu-v1.0.sh
```
Проверь shell-синтаксис:
```sh
sh -n /tmp/xmenu-v1.0.sh
busybox ash -n /tmp/xmenu-v1.0.sh
```
Если ошибок нет, установи файл с резервной копией:
```sh
mkdir -p /opt/bin /opt/etc/xkeen-menu/backups
if [ -f /opt/bin/xmenu ]; then
  cp -p /opt/bin/xmenu "/opt/etc/xkeen-menu/backups/xmenu-before-update-$(date +%Y%m%d-%H%M%S).sh"
fi
cp /tmp/xmenu-v1.0.sh /opt/bin/xmenu && chmod 700 /opt/bin/xmenu
sh -n /opt/bin/xmenu && /opt/bin/xmenu
```
Не рекомендуется `curl URL | sh`: при потоковом запуске сложнее изучить файл, проверить его синтаксис и сохранить исходную версию до исполнения.

### Запуск и проверка
```sh
sh -n /opt/bin/xmenu
busybox ash -n /opt/bin/xmenu
/opt/bin/xmenu
```
Если `/opt/bin` входит в `PATH`, можно запустить командой `xmenu`. Если короткая команда не находится, используй полный путь.

## Информация об устройстве
### Модель и KeeneticOS
Xmenu обращается к локальному RCI API:
```text
http://127.0.0.1:79/rci/show/version
```
Если данные неполные или API недоступен, скрипт использует `ndmc` и Device Tree (`/proc/device-tree/model`, `/proc/device-tree/compatible`). Для известных идентификаторов Hopper/NC-3811 имя модели может нормализоваться до `Hopper (NC-3811)`.

### Архитектура Entware
Порядок определения: `opkg print-architecture` → `/opt/etc/opkg.conf` → `uname -m`. Выводится архитектура Entware, например `aarch64`, а не маркетинговое название процессора. Код нормализует `aarch64`, `mipsel`, `mips`, `x86_64` и `x86`; 32-битные ARM-варианты не должны ошибочно выдаваться за `aarch64`.

### Список установленных компонентов
Таблица формируется на основе пакетов `opkg`, исполняемых файлов, init-скриптов и локальных файлов версии. Показываются только обнаруженные установленные компоненты. Если версия не извлечена, Xmenu пишет `версия неизвестна`; это само по себе не доказывает неисправность приложения.

## Стратегии NFQWS
### Пункт 11 — выбрать и применить
Стратегии скачиваются из репозитория `nfqws-menu` и кэшируются локально. Популярные имена выводятся в заданном приоритетном порядке; остальные файлы сортируются по имени.

При применении Xmenu:
1. Проверяет выбранное имя и наличие стратегии в кэше/манифесте.
2. Сверяет SHA-256, когда ожидаемый хеш доступен.
3. Подготавливает временную копию стратегии.
4. Сохраняет `ISP_INTERFACE`, если он был задан в текущем конфиге.
5. Переносит привязку `rkn.list` в новый `MODE_LIST`, если она была в старой стратегии.
6. Проверяет и загружает необходимые blobs/lists.
7. Создаёт резервную копию активного конфига.
8. Применяет новую конфигурацию, записывает маркер выбранной стратегии и пытается перезапустить соответствующий сервис.

Пути активных конфигов:
| Движок | Конфигурация | Init-скрипт |
|---|---|---|
| NFQWS v1 | `/opt/etc/nfqws/nfqws.conf` | `/opt/etc/init.d/S51nfqws` |
| NFQWS2 | `/opt/etc/nfqws2/nfqws2.conf` | `/opt/etc/init.d/S51nfqws2` |

Применение требует подтверждения. Если необходимые файлы не удалось подготовить, Xmenu отменяет замену конфига.

### Защита кастомной стратегии — пункт 12
Перед синхронизацией Xmenu сравнивает текущий конфиг с сохранённой стратегией из кэша. Автоматическое обновление допускается только при совпадении исходного конфига с этой стратегией.

При сравнении игнорируются комментарии, пустые строки, `ISP_INTERFACE` и добавленная Xmenu привязка `rkn.list`. Если конфиг отличается, маркер стратегии сам по себе не является разрешением на замену: кастомный конфиг оставляется без автоматической подмены.

## Blobs, lists и rkn.list
### Пункт 12 — файлы активной конфигурации
Xmenu извлекает пути blobs (`.bin`) и списков (`.list`) из активного конфига. Для blobs использует манифест SHA-256: уже совпадающие файлы повторно не скачиваются, новые файлы проверяются до установки. При замене существующего файла создаётся резервная копия, если это возможно. Симлинки и подозрительные имена не перезаписываются автоматически.

### Пункт 13 — набор blobs NFQWS2
Целевой каталог:
```text
/opt/etc/nfqws2/blobs
```
Операция получает `SHA256SUMS`, валидирует формат записей, проверяет имеющиеся blobs и загружает недостающие. При частичных ошибках сообщает результат и возвращает ошибочный код, а не объявляет весь процесс успешным.

### Пункт 14 — обновление rkn.list
Главное меню делегирует обновление функции `update_rkn_list` из актуального upstream-скрипта `nfqws-menu`. Поэтому конкретные шаги выбора/обновления определяются текущей версией этого проекта.

В коде также имеется обработчик путей списка:
| Движок | Конфиг | Путь списка |
|---|---|---|
| NFQWS v1 | `/opt/etc/nfqws/nfqws.conf` | `/opt/etc/nfqws/rkn.list` |
| NFQWS2 | `/opt/etc/nfqws2/nfqws2.conf` | `/opt/etc/nfqws2/lists/rkn.list` |

Этот обработчик проверяет минимальный размер загруженного списка, сохраняет существующий файл перед заменой и добавляет `--hostlist` к `MODE_LIST`, если он ещё не подключён. Не считай число доменов фиксированным: список может меняться в upstream-репозитории.

## Профили XKeen
### XKeen Stable
Для установщика проверяются ключевые строки и shell-синтаксис. Xmenu подготавливает копию скрипта и предотвращает автоматический запуск вложенного интерактивного шага `xkeen -i` в конце установщика, чтобы управлять дальнейшей настройкой профиля.

### Ядра Xray и Mihomo
Для определения релиза используются GitHub API:
- Xray: `XTLS/Xray-core` и команда XKeen `-ux <tag>`.
- Mihomo: `MetaCubeX/mihomo` и команда XKeen `-um <tag>`.

При наличии `jq` JSON обрабатывается через `jq`; иначе используется запасной разбор. Перед крупной установкой проверяется свободное место в `/opt`.

### XKeen Auto
Профили вызывают XKeen с параметрами:
```text
xkeen -i auto cores=none geo=on geoipset=on cron=on autostart=on
```
После настройки Xmenu старается назначить ежедневное обновление GeoIP/GeoIPSet на 04:30 по времени роутера. Для расписания необходимы `crontab` и исполняемый `/opt/sbin/xkeen`. Проверь часы и часовой пояс роутера.

### Комбинированные профили 9 и 10
Порядок: выбранное ядро и XKeen Auto → XKeen UI zxc-rv → NFQWS2 → NFQWS Web. Если обязательный шаг завершается ошибкой, профиль останавливается и указывает неудавшийся шаг. Установленное другое ядро автоматически не удаляется.

## Утилиты и диагностика
### 15. DPI Detector
Rust-установка в текущем коде рассчитана на архитектуру `aarch64`. Используется официальный установщик из ветки `rust` репозитория `Runnin4ik/dpi-detector`, с CDN-зеркалом как запасным источником. Скрипт проверяет ожидаемые маркеры, синтаксис и запуск установленного бинарного файла. Если бинарник не запускается из-за отсутствующего loader/несовместимости, Xmenu сообщает об этом и пытается переустановить Rust-версию.

### 16. TG WS Proxy Rust
Вызов делегируется `menu_tg_ws_proxy_rs` в `nfqws-menu`. Веб-панель может быть доступна без пароля внутри LAN; не публикуй порт панели напрямую в WAN без собственной настройки контроля доступа и firewall.

### 17. KeenKit
Если `/opt/keenkit.sh` существует, Xmenu предлагает запустить его. Если скрипт не обнаружен, запрашивается подтверждение установки из репозитория KeenKit.

### 18. awg-manager
Xmenu выводит напоминание о WireGuard-компоненте Keenetic и вызывает `menu_awg_manager` из `nfqws-menu`. Дальнейшая установка зависит от актуального upstream-действия и настроенных источников пакетов.

### 19. Статус и версии
Выводит сведения об устройстве и найденных компонентах, активной стратегии, а также признаки запуска Mihomo/nfqws2 по списку процессов. Дополнительно показывает наличие cron-задания обновления GeoIP/GeoIPSet и синхронизации стратегий, если такие записи обнаружены.

## Удаление компонентов
### Пункт 21 — цифровое меню удаления
В меню отображаются обнаруженные компоненты, среди которых могут быть XKeen, обе версии XKeen UI, DPI Detector, awg-manager, TG WS Proxy Rust, KeenKit, пакеты NFQWS, NFQWS UI, Xray и Mihomo. Фактический список зависит от пакетов, файлов и init-скриптов на конкретном устройстве.

Опасные действия требуют подтверждения. Общие зависимости не удаляются автоматически при удалении отдельной панели. Для удаления всех пакетов NFQWS предусмотрено отдельное действие; конфиги предполагается сохранять.

### Резервные файлы
Подменю позволяет искать `*.bak`, `*.bak.*` и `*-opkg` в выбранных каталогах конфигурации. Сначала показывается список файлов, затем запрашивается отдельное подтверждение удаления. Не очищай резервные копии до проверки результата обновления.

### Пункт 22 — удалить Xmenu
Удаляет `/opt/bin/xmenu` и связанные cron-задания Xmenu. Отдельное подтверждение может разрешить очистку кэша, манифестов и резервных копий Xmenu. Удаление самого Xmenu не предназначено для удаления XKeen, NFQWS2 или других компонентов: они удаляются отдельно.

## Обновление Xmenu
Пункт `23` загружает скрипт с адреса:
```text
https://raw.githubusercontent.com/RaNgeRwWs/Xmenu/main/xmenu-v1.0.sh
```
До замены проверяются минимальный размер, shebang, ключевые маркеры, отсутствие очевидной HTML-ошибки и синтаксис `sh -n`. Если установленный файл существует, Xmenu пытается сохранить его в каталоге резервных копий. После успешной замены скрипт перезапускается.

Эти проверки помогают предотвратить установку пустого/повреждённого файла, но не являются цифровой подписью. Перед публикацией новой версии убедись, что файл в `main` содержит именно ожидаемый релиз.

Не удаляй эти пути вручную, пока не проверил, что они не используются другими компонентами.

## Безопасность
Xmenu запускает сторонние установщики с правами `root`. Используй его только если доверяешь источникам и понимаешь, какие компоненты выбираешь.

В зависимости от типа файла код использует HTTPS, таймауты, повторные попытки, зеркала, минимальный размер файла, проверку структуры и `sh -n`. Для части файлов используются SHA-256-манифесты или контрольные суммы, опубликованные источником.

Важно понимать:
- `sh -n` проверяет синтаксис, а не безопасность логики.
- HTTPS не доказывает, что опубликованный скрипт корректен.
- Хеш, полученный с того же источника, не заменяет подпись издателя.
- Не все сторонние shell-установщики имеют независимую криптографическую проверку.
- Зеркало повышает шанс загрузки, но не является независимой гарантией доверия.
- Изменение сетевых стратегий и веб-панелей может повлиять на подключение к роутеру и безопасность LAN.

Перед операцией сохраняй конфиги, не выставляй панели управления в WAN и не очищай бэкапы до проверки результата.
