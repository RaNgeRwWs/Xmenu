### Установить стабильный релиз

Подключись к Entware по SSH и выполни:

```sh
mkdir -p /opt/bin && curl -fL --retry 3 'https://github.com/rangerxxyy/Xmenu/releases/latest/download/xmenu-v1.0.sh' -o /tmp/xmenu.sh && sh -n /tmp/xmenu.sh && { [ ! -f /opt/bin/xmenu ] || cp -p /opt/bin/xmenu "/opt/bin/xmenu.bak.$(date +%Y%m%d-%H%M%S)"; } && cp /tmp/xmenu.sh /opt/bin/.xmenu-new && chmod 700 /opt/bin/.xmenu-new && mv -f /opt/bin/.xmenu-new /opt/bin/xmenu && xmenu
```

Далее для запуска достаточно:

```sh
xmenu
```

## Что умеет Xmenu

| Раздел | Возможности |
| --- | --- |
| 📦 Компоненты | XKeen Stable, Xray, Mihomo, панели XKeen UI, NFQWS v1/v2 и веб-интерфейсы |
| 🧩 Стратегии | Каталог из 40 вариантов NFQWS2, контрольные суммы, кэш и резервное копирование |
| 🌐 DNS | Текущие DNS интернет-фильтров, DoT/DoH, привязки доменов и статические hosts |
| 🎙 Discord | Обработка голосовой UDP-сессии в NFQWS2, исключение из ускорения и интеграция с XKeen |
| 🛠 Обслуживание | Зеркала Entware, копии `opkg.conf`, Dropbear Fix, сжатие UPX и удаление компонентов |
| 🔎 Диагностика | Проверка сайта, DNS-серверов и доступности VPS, запуск DPI Detector |

Xmenu работает поверх Entware: выполняет пакетные команды, запускает установщики выбранных компонентов и управляет их конфигурациями. Основные действия доступны через меню и команды SSH.

## Быстрые сценарии

Выбери задачу и пройди по указанным пунктам. Например, **12 → 6 → 2** означает: главное меню → управление NFQWS2 → настройки DNS → добавить DoH.

| Хочу… | Куда перейти | Что получится |
| --- | --- | --- |
| Установить NFQWS2 | **4** | Пакет NFQWS2 и его штатные файлы |
| Сразу настроить XKeen с Mihomo | **7** | Ядро, геофайлы, расписание обновления и автозагрузка |
| Применить готовую стратегию | **12 → 1** | Проверенная конфигурация с копией предыдущей |
| Подготовить все fake-пакеты | **12 → 2** | Каталог blobs NFQWS2 |
| Проверить зависимости действующего конфига | **12 → 3** | Проверка blobs и списков текущей стратегии |
| Добавить защищённый DNS | **12 → 6 → 1 / 2** | Общий DoT или DoH либо сервер для указанного домена |
| Направить отдельный домен к другому DNS | **12 → 6 → 3** | Готовая доменная привязка; для собственного домена — добавление DoT/DoH с заполнением поля домена |
| Попробовать исправить обрыв голоса Discord | **12 → 9 → 2** или **S → 3 → 2** | Правила обработки UDP-сессии в NFQWS2 |
| Сменить зеркало Entware | **22 → 3** | Новый источник пакетов и копия прежнего opkg.conf |
| Сохранить opkg.conf | **22 → 4 → 1** | Отдельная резервная копия |
| Восстановить opkg.conf | **22 → 4 → 2** | Последняя копия, созданная Xmenu |
| Обновить списки доступных пакетов | **22 → 5** | Новые индексы Entware |
| Обновить Xmenu | **21** | Проверка загрузки и замена скрипта с резервной копией |
| Удалить отдельный компонент | **19** | Список действий удаления с подтверждениями |

> [!TIP]
> Перед экспериментами со стратегиями создай архив командой `xmenu backup`. Копии `opkg.conf` управляются отдельно через **22 → 4**.

### Пункты 1–7: отдельные компоненты

## Управление nfqws2

Открывается пунктом **12**. Стратегии и синхронизация используют найденный активный конфиг с приоритетом NFQWS2. Для IPSet, rkn.list и обхода DNS при установленных v1/v2 доступен выбор версии или обеих сразу.

```text
1.  Выбрать и применить стратегию nfqws
2.  Установить все blobs nfqws2
3.  Скачать/проверить blobs и lists активной стратегии
4.  Скачать rkn.list (nfqws / nfqws2)
5.  Обход блокировки DoT/DoH
6.  Настройки текущих DNS-серверов
7.  Обновить Ipset Lists
8.  Смена текущих fake:blob
9.  Discord: включить/выключить фикс
10. Обновление hosts
0.  Назад
```

### 1. Выбрать и применить стратегию

Показывает каталог конфигураций для выбранной версии. Основной список NFQWS2 сохраняет **40 вариантов**. Пункт **99 — Дополнительные конфигурации** открывает отдельный список из **30 файлов**. Среди них есть переработанные версии конфигураций из основного каталога; это два отдельных списка, а не заявление о 70 уникальных методах обхода.

- Активная стратегия определяется сравнением с действующим конфигом.
- Манифест с контрольными суммами кэшируется на час; конфиги скачиваются по выбору.
- Для дополнительных стратегий манифест и конфиг берутся из одной ревизии репозитория.
- Перед заменой сохраняется резервная копия, проверяется SHA-256 и синтаксис конфигурации.
- После применения перезапускается соответствующий сервис; ошибка перезапуска выводится отдельно.

Проверенный локальный кэш используется при недоступности загрузки. Работоспособность конкретной стратегии зависит от провайдера, версии NFQWS и маршрута трафика.

<details>
<summary><b>Пошагово: выбрать стратегию и проверить результат</b></summary>

1. Установи NFQWS2 через пункт **4**, если пакет ещё отсутствует.
2. Открой **12 → 1**. При доступном источнике загрузится каталог; при наличии проверенного кэша он может быть использован повторно.
3. Выбери конфигурацию по её номеру.
4. Xmenu проверит SHA-256 загруженного файла, подготовит конфиг и ресурсы, создаст резервную копию и заменит действующий файл.
5. Дождись сообщения о перезапуске службы. При его ошибке проверь конфиг и вывод `/opt/etc/init.d/S51nfqws2 status`.
6. Проверь нужные сайты и приложения из своей сети. Успешная проверка файла означает его целостность и корректный shell-синтаксис; результат обхода зависит от условий подключения.

<details>
<summary><b>Что сохраняется при замене стратегии</b></summary>

| Данные | Поведение Xmenu |
| --- | --- |
| Предыдущий конфиг | Сохраняется в резервной копии до замены |
| `ISP_INTERFACE` | Переносится из действующего конфига буквально, включая список интерфейсов |
| Подключённый `rkn.list` | Его привязка сохраняется при подготовке новой стратегии |
| Ручные изменения остальных аргументов | Новая стратегия задаёт свои значения; прежние остаются в копии конфига |
| Активный вариант | Определяется сравнением конфигурации с проверенным кэшем |

Если у тебя собственные параметры политик, портов или IPv6, сравни новый конфиг с резервной копией перед дальнейшими ручными изменениями. Xmenu не обещает автоматически объединить все пользовательские аргументы с другой стратегией.

</details>

<details>
<summary><b>Как выбирается v1 или v2</b></summary>

| Операция | Выбор версии |
| --- | --- |
| Стратегия и синхронизация активных ресурсов | При наличии двух конфигов приоритет имеет NFQWS2; если он отсутствует, используется NFQWS v1 |
| Смена fake:blob | При двух конфигурациях открывается выбор v1 / v2 |
| rkn.list, IPSet, обход блокировки DoT/DoH | При двух установленных версиях можно выбрать одну либо обе |
| Discord Fix | Работает с NFQWS2 |
| Настройка DNS и hosts | Изменяет настройки самой прошивки Keenetic через ndmc |

Основной конфиг v1 — `/opt/etc/nfqws/nfqws.conf`; v2 — `/opt/etc/nfqws2/nfqws2.conf`. Доступность выбора определяется найденными конфигами или установленными пакетами в зависимости от операции.

</details>

<details>
<summary><b>Чем отличаются blobs, lists, IPSet и rkn.list</b></summary>

| Термин | Что хранится | Для чего нужен |
| --- | --- | --- |
| **Стратегия** | Shell-конфигурация `.conf` | Задаёт фильтры трафика, аргументы обработки, порты и пути к ресурсам |
| **Blob** | Бинарный файл `.bin` | Содержит данные fake-пакета или другого ресурса стратегии |
| **Hostlist / lists** | Текстовый список доменов | Ограничивает применение стратегии указанными именами |
| **IPSet list** | IP-адреса и сети CIDR | Выбирает трафик по адресам назначения |
| **rkn.list** | Отдельный доменный список | Подключается к конфигу как дополнительный hostlist |
| **hosts** | Пары `IP DOMAIN` | Создаёт статические DNS-привязки в прошивке роутера |

Пункт **12 → 2** загружает все доступные blobs NFQWS2. Пункт **12 → 3** работает с зависимостями активного конфига. **12 → 7** заменяет конкретный IPSet-список, а **12 → 10** управляет статическими DNS-привязками.

</details>


### 2. Установить все blobs NFQWS2

Скачивает каталог `.bin`-ресурсов в `/opt/etc/nfqws2/blobs`. Проверяет уже имеющиеся файлы и сверяет загруженные с контрольными суммами. В конце сообщает число обработанных файлов и ошибок.

**Когда использовать:** после первой установки NFQWS2 или перед проверкой нескольких стратегий, использующих разные fake-пакеты.

### 3. Проверить ресурсы активной стратегии

Разбирает пути к blobs и lists в действующем конфиге, проверяет наличие нужных файлов и загружает отсутствующие ресурсы. Обрабатывает зависимости текущего конфига, а не весь доступный каталог.

Если действующий конфиг совпадает с ранее выбранной и сохранённой в кэше стратегией, синхронизация также может обновить этот вариант из свежего каталога. При ручных изменениях, из-за которых конфиг перестал совпадать с кэшем, автоматическая замена стратегии пропускается; проверяются её ресурсы.

### 4. Скачать rkn.list

Обновляет доменный список для выбранного NFQWS, при необходимости добавляет ссылку на него в конфигурацию. Изменения сохраняются с резервной копией; сервис перезапускается, когда список или конфиг действительно изменились.

### 5. Обход блокировки DoT/DoH

Добавляет стратегию доступа к публичным защищённым DNS в `NFQWS_ARGS_CUSTOM`: для v1 используется классический desync, для v2 — Lua-стратегия. Проверяет наличие порта `853` в `TCP_PORTS` и `UDP_PORTS`, сохраняет конфиг и перезапускает выбранную службу.

Стратегия загружается отдельным файлом; при недоступности источника используется встроенный вариант. Ответ `n` отменяет действие **до загрузки, резервного копирования и записи**.

**Эта операция помогает получить доступ к DNS-сервисам.** Настройка самих DNS-серверов находится в следующем пункте.

### 6. Настройки текущих DNS-серверов

Открывает встроенное управление DNS Keenetic через `ndmc`. Подробное описание — [ниже](#настройки-dns-серверов).

### 7. Обновить IPSet Lists

Предлагает большой IP/CIDR-список Flowseal или стандартный список выбранного пакета. Можно обработать v1, v2 или обе версии.

| Версия | Файл |
| --- | --- |
| NFQWS v1 | `/opt/etc/nfqws/ipset.list` |
| NFQWS2 | `/opt/etc/nfqws2/lists/ipset.list` |

Перед записью удаляются комментарии и пустые строки, проверяется непустой результат и сохраняется резервная копия. После обновления перезапускается соответствующая служба. Большой список увеличивает объём обрабатываемых адресов и потребление ресурсов роутера.

### 8. Смена текущих fake:blob

Находит именованные `fake:blob=NAME` по секциям конфига и показывает файл, на который указывает `--blob=NAME:...`. Hex-значения пропускаются, повторяющиеся имена объединяются.

После выбора предлагает локальные `.bin`, файлы из манифеста или резервного каталога. Скачивает выбранный ресурс, переназначает путь `--blob`, проверяет shell-синтаксис и сохраняет конфигурацию с бэкапом. Перезапуск службы выполняется по подтверждению.

### 9. Discord Fix

Направляет UDP-пакеты голосовой сессии на портах **19294–19344** и **50000–50100** в NFQWS2 на протяжении звонка. При наличии цели `PPE` исключает эти потоки из ускорения прошивки. Учитывает интерфейсы, номер очереди и политики выбранной конфигурации NFQWS2, включая значения из `.run`.

```text
1. Статус / диагностика
2. Включить фикс
3. Выключить фикс
4. XKeen: исключить порты Discord   [если установлен XKeen]
0. Назад
```

При включении создаются собственные цепочки firewall, init-скрипт и хук восстановления правил. Выключение снимает правила Xmenu и удаляет файлы включения фикса. Пункт XKeen добавляет порты в `port_exclude.lst` и предлагает перезапуск работающего XKeen.

Фикс обеспечивает обработку сессии; подходящая стратегия Discord должна быть в конфигурации NFQWS2. После включения переподключись к голосовому каналу.

### 10. Обновление hosts

Загружает список статических DNS-привязок, разбитый на секции. Можно выбрать несколько секций через запятую, все записи, удалить домены из этого списка или посмотреть текущие привязки.

```text
1…N. Секции hosts-файла
  a. Все секции
 88. Удалить домены из этого hosts-файла
 99. Показать текущие записи
  0. Назад
```

Записи применяются командой `ip host DOMAIN IP`, удаляются через `no ip host DOMAIN`. Поддерживается IPv4; некорректные адреса и домены пропускаются, для каждого домена сохраняется один IP. Перед изменением создаётся копия текущих `ip host`, затем сохраняется конфигурация Keenetic. При выборе более 64 доменов показывается предупреждение о лимите роутера.

## Утилиты и диагностика

### Диагностика сайта

Откройте **13 → Диагностика сайта** и введите домен или ссылку. Без указания протокола используется HTTPS. Можно указать путь страницы и порт.

```text
Подключение: через текущие настройки роутера
Сайт / IP           DNS     TCP       TLS             HTTP / ответ
1. example.com
IPv4 сайта          20 мс   30 мс     TLS1.3 40 мс    HTTP 301 · 50 мс
2. www.example.com
IPv4 сайта          15 мс   25 мс     TLS1.3 35 мс    HTTP 200 · 45 мс

Итог
Сайт открывается — HTTP 301 → HTTP 200
Тест 2/2 — принудительно напрямую
```

Диагностика различает отсутствие DNS-ответа, отказ TCP, отсутствие маршрута, сброс соединения, сбой TLS, ошибку сертификата, ответ сайта и обрыв чтения. Отдельно проверяются до двух адресов каждой версии IP. Все переходы и адреса собраны в одной таблице: DNS, TCP, TLS и HTTP с временем этапов. Итог обычным регистром содержит подтверждение: например, «Сайт открывается — HTTP 301 → HTTP 200». Низкоуровневые сообщения Python/OpenSSL скрыты. Лимит — 50 секунд на сайт; тайм-аут сам по себе не означает блокировку.

Выполняется HTTP/1.1 GET с чтением до 16 КиБ ответа и проверкой до пяти перенаправлений. Цикл, отсутствующий адрес перехода и переход HTTPS → HTTP отмечаются явно. Для HTTPS проверяются имя сайта и доверие к сертификату. HTTP 403 означает ограничение доступа сервером, а не ошибку DNS. JavaScript и ресурсы полной страницы не загружаются.

Для каждого сайта автоматически выполняются два прогона: **1/2 — обычное подключение**, **2/2 — принудительно напрямую через WAN**. Во втором прогоне DNS идёт через проверенный DoH, TCP/TLS/HTTP используют метку обхода и WAN-интерфейс. Если прямой маршрут не подтверждён, проверка не подменяется обычным подключением. При ошибке обычного DNS контрольный DoH не скрывает исходную проблему. Временные исключения очищаются; службы не отключаются, постоянные настройки не меняются, отчёты в файлы не сохраняются. После обоих прогонов Enter возвращает назад.

TCP в таблице — время установки соединения с точностью до десятых миллисекунды, а не ICMP ping. При прозрачном прокси оно может отражать локальное принятие соединения; такие значения не выдаются за задержку до удалённого сайта.

Нужны Python 3 с TLS и доверенные сертификаты. При отсутствии Python обычная проверка использует прежний базовый curl HEAD; прямой режим требует Python. Методика разделения DNS/TCP/TLS/HTTP сверена с [OONI Web Connectivity](https://github.com/ooni/spec/blob/master/nettests/ts-017-web-connectivity.md), измерение этапов — с [документацией curl](https://curl.se/docs/manpage.html).

Запуск по SSH:

```sh
xmenu site-check https://example.com
```

Принудительно напрямую:

```sh
xmenu site-check --direct https://example.com
```

### Проверка DNS-серверов

Откройте **13 → Проверка DNS-серверов**. До начала теста выберите популярные серверы, весь каталог, отдельные номера или собственные IPv4/IPv6. Для ручного ввода можно задать порт UDP, имя и порт DoT, SNI и URL DoH. Пресеты и свои серверы используют одинаковые проверки; каждый протокол обращается к адресу соответствующего сервиса.

```text
Провайдер     DoH       DoT       UDP       UDP-резолвер            Spoofing
Google       24.1 мс   20.3 мс    3.4 мс   8.8.4.4 → GOOGLE        0/5
Cloudflare   32.0 мс   28.7 мс    5.1 мс   1.1.1.1 → CLOUDFLARE    0/5
```

| Столбец | Что показывает |
| --- | --- |
| **DoH / DoT / UDP** | Время DNS-запроса. Недоступный метод, Timeout, SYN Drop, TLS Drop и ошибка сертификата отображаются в самой ячейке. |
| **UDP-резолвер** | Обнаруженный исходящий адрес резолвера и организация; отсутствие данных обозначается явно. Ширина столбца ограничена. |
| **Spoofing** | Число подозрительных ответов среди выполненных контрольных проверок. Это результат проб, а не процент достоверности блокировки. |

Проверяются ответы контрольных доменов, несуществующее имя, признаки Fake-IP и ответы независимых DNS. Цвета отделяют успешные проверки, подозрительные ответы и ошибки. Отсутствие данных об организации не считается подтверждением подмены. DNS с собственной фильтрацией может ограничивать отдельные домены.

В каталоге больше 30 вариантов: Google, Cloudflare, Quad9, AdGuard, Alibaba, CleanBrowsing, Comss, ControlD, DNS.SB, NextDNS, OpenDNS, Яндекс и другие. Протокол, которого нет в пресете сервиса, не проверяется. Нужны Python 3 с ssl, curl/libcurl и доверенные сертификаты. Enter возвращает назад; отчёты в файлы не сохраняются.

```sh
xmenu dns-check
```

### Доступность VPS-сервера

Откройте **13 → Доступность VPS-сервера** и введите публичный IP. Xmenu автоматически проверит прямой маршрут через WAN, ICMP, основные TCP-порты, UDP/QUIC, SSH, TLS и HTTPS. Внешние узлы при обычном запуске всегда проверяют ICMP, TCP/443 и TCP/22 (SSH). При неоднозначных результатах расширяется набор локальных портов. Домен и доступ к VPS не нужны.

Дополнительно используются поиск ранее замеченных портов InternetDB с последующей живой проверкой, STUN Binding, ICMP Timestamp для IPv4, видимость BGP-маршрута у RIS-наблюдателей и проверка RPKI. Для найденного дополнительного порта возможно сравнение с внешними узлами. Локальная таблица firewall проверяется отдельно: потенциальный запрет на самом роутере снижает уверенность в выводе о внешней фильтрации.

Итог отдельно показывает доступность адреса и возможную причину проблемы. Таймаут, закрытый порт и ошибка TLS не считаются доказательством блокировки провайдером. Если обход VPN/прокси не подтверждён, отображается `DIRECT_PATH_UNVERIFIED`.

## Сервисное меню

Нажми **S** в главном меню.

```text
1. Dropbear Fix
2. Сжать bin/sbin
3. Discord Fix
0. Назад
```

### Dropbear Fix

Переносит Entware Dropbear с порта `22` на `222` и исправляет PID-файл с `/opt/var/run` на `/var/run`. Сохраняет изменяемые файлы и проверяет результат перед перезапуском.

Есть два варианта: исправить порт и PID-файл или дополнительно сбросить пароль root Entware на `keenetic`. Сброс требует отдельного выбора и подтверждения. Перезапуск SSH выполняется в фоне и может разорвать текущую сессию; повторное подключение — на порт `222`.

### Сжать bin/sbin

Обрабатывает поддерживаемые исполняемые файлы в `/opt/bin` и `/opt/sbin` через UPX. Уже сжатые или неподдерживаемые файлы пропускаются. Для распаковки отдельного файла используется `upx -d ПУТЬ`.

### Discord Fix

Открывает то же управление голосовым UDP-трафиком, что **12 → 9**. Описание действий приведено в [разделе Discord Fix](#9-discord-fix).

## OPKG и зеркала Entware

Открывается пунктом **22**. Показывает текущий адрес репозитория, а при ручном выборе — регион и активное зеркало.

```text
1. Авто-выбор Entware
2. Проверить доступность зеркал Entware
3. Выбрать зеркало Entware вручную
4. Копии opkg.conf
5. Выполнить opkg update
0. Назад
```

| № | Действие | Результат |
| --- | --- | --- |
| 1 | **Авто-выбор** | Проверяет зеркала и выбирает доступный источник с лучшим измеренным откликом. |
| 2 | **Проверить доступность** | Показывает статус, регион, адрес и результаты загрузки индекса каждого зеркала. |
| 3 | **Выбрать вручную** | Открывает каталог зеркал с текущим выбором; смена источника сохраняет прежний конфиг. |
| 4 | **Копии opkg.conf** | Открывает создание, восстановление и удаление резервных копий. |
| 5 | **opkg update** | Обновляет локальные индексы доступных пакетов. Установленные пакеты эта команда не обновляет. |

Проверка скачивает и анализирует `Packages.gz`: HTML-страница блокировки, повреждённый архив или ответ без корректного индекса не считаются рабочим зеркалом. При сбое загрузки используется ограниченное число повторов и резервный загрузчик.

### Копии opkg.conf — пункт 22 → 4

```text
1. Создать копию opkg.conf
2. Восстановить копию opkg.conf
3. Удалить все копии opkg.conf
0. Назад
```

- **Создать** — сохраняет текущий `/opt/etc/opkg.conf` с датой и уникальным именем в `/opt/etc/xmenu/backups/`.
- **Восстановить** — выбирает последнюю сохранённую Xmenu копию; перед заменой сохраняет текущий конфиг и запрашивает подтверждение.
- **Удалить все копии** — перечисляет найденные резервные файлы `opkg.conf` и удаляет их после подтверждения. Рабочий `opkg.conf` и копии других конфигураций сохраняются.

После смены зеркала новый источник действует сразу. Чтобы перечитать индекс пакетов, запусти **22 → 5**.

### Полное удаление Xmenu и всех его резервных копий

Выйдите из Xmenu и выполните по SSH от root одну команду:

```sh
sh -c 'set -e; t=$(mktemp); trap '\''rm -f "$t" "$t.new"'\'' 0; if command -v crontab >/dev/null 2>&1 && crontab -l > "$t" 2>/dev/null; then { grep -Fv "/opt/bin/xmenu sync" "$t" || :; } > "$t.new"; crontab "$t.new"; fi; rm -f /opt/bin/xmenu /opt/bin/xmenu.bak*; rm -rf /opt/etc/xmenu /opt/etc/xkeen-menu'
```

Удаляются команда `xmenu`, её копии `xmenu.bak*`, данные и все резервные копии в `/opt/etc/xmenu`, прежний каталог `/opt/etc/xkeen-menu` и задача автосинхронизации Xmenu в cron. **Резервные копии из этих каталогов будут удалены без подтверждения.** Установленные XKeen, NFQWS, панели и их действующие настройки сохраняются. Общий каталог стратегий `/opt/etc/nfqws-menu/strategies` также сохраняется, поскольку может использоваться другим меню.

## Обновление Xmenu

- **U** в главном меню проверяет наличие новой версии и выводит результат.
- **21** загружает обновление Xmenu, проверяет файл и сохраняет установленную версию перед заменой.

Проверка обновлений выполняется независимо от `opkg update`. Наличие нового релиза не запускает замену файлов автоматически.

## Если что-то не работает

<details>
<summary><b>Не скачивается файл или недоступно зеркало</b></summary>

Проверь работу DNS и доступ по HTTPS. Попробуй GitHub Raw или зеркало из раздела установки. Для Entware открой **22 → 2**: Xmenu проверит именно индекс пакетов и покажет результат, а не только доступность адреса.

</details>

<details>
<summary><b>Компонент установлен, но не работает</b></summary>

Проверь требования компонента, архитектуру Entware (`opkg print-architecture`), свободное место (`df -h /opt`), его конфигурацию и журнал службы. Успешная установка пакета сама по себе не подтверждает работоспособность стратегии в сети провайдера.

</details>

<details>
<summary><b>После изменения DNS не открываются сайты</b></summary>

Проверь URI DoH или адрес, порт и SNI DoT. Посмотри DNS интернет-фильтров и общие серверы в **12 → 6**. Для удаления добавленного общего сервера используй пункт 4 этого экрана. Если доступ к публичным DNS блокируется провайдером, проверь стратегию обхода в **12 → 5**.

</details>

<details>
<summary><b>Discord теряет голосовое соединение</b></summary>

Открой **12 → 9 → 1**, проверь работающий NFQWS2, правила NFQUEUE/PPE и исключения XKeen. После включения фикса переподключись к голосовому каналу. При отсутствии подходящей стратегии в NFQWS2 один fullsession-фикс не обеспечивает обход блокировки.

</details>

При сообщении об ошибке укажи версию Xmenu, модель роутера, версию прошивки, архитектуру и точный пункт меню. Прикладывай полный вывод ошибки без паролей, токенов и приватных ключей.

<details>
<summary><b>Вернуть предыдущую конфигурацию NFQWS2</b></summary>

Найди копию, созданную перед неудачным изменением:

```sh
ls -lt /opt/etc/xmenu/backups/nfqws2.conf.*.bak
```

Скопируй нужный файл во временный путь, проверь его и сохрани текущую конфигурацию перед восстановлением:

```sh
cp /opt/etc/xmenu/backups/ИМЯ_КОПИИ.bak /tmp/nfqws2-restore.conf &&
sh -n /tmp/nfqws2-restore.conf &&
cp -p /opt/etc/nfqws2/nfqws2.conf "/opt/etc/nfqws2/nfqws2.conf.before-restore.$(date +%Y%m%d-%H%M%S).bak" &&
cp /tmp/nfqws2-restore.conf /opt/etc/nfqws2/.nfqws2-restore.conf &&
mv /opt/etc/nfqws2/.nfqws2-restore.conf /opt/etc/nfqws2/nfqws2.conf &&
/opt/etc/init.d/S51nfqws2 restart
```

Замени `ИМЯ_КОПИИ.bak` реальным именем из вывода `ls`. Для v1 используются его конфиг, каталог и init-скрипт. Восстановление `opkg.conf` удобнее выполнить через **22 → 4 → 2**.

</details>
