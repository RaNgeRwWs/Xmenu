## 👋 О проекте

**Xmenu** — интерактивный shell-скрипт для управления сетевыми компонентами на роутерах **Keenetic / Netcraze** с установленным **Entware**. Он запускается из SSH и объединяет в одном цифровом меню несколько установщиков, профили XKeen, работу со стратегиями NFQWS/NFQWS2 и базовую диагностику.

Проект рассчитан на пользователей, которые управляют Keenetic / Netcraze через SSH и понимают базовые риски изменения сетевых настроек.

## ✨ Возможности

- 🧩 **XKeen:** установка XKeen Stable, двух вариантов XKeen UI и готовых профилей с Xray или Mihomo.
- 🌐 **NFQWS / NFQWS2:** запуск установщиков движков, веб-панели и UI.
- 🎛️ **Профили установки:** настройка XKeen Auto, GeoIPSet и связанных компонентов выбранным сценарием.
- 🎯 **Стратегии:** выбор и применение стратегии NFQWS, проверка активной конфигурации.
- 📦 **Blobs и lists:** загрузка необходимых файлов для активной стратегии и установка blobs NFQWS2.
- 🧾 **RKN list:** запуск предусмотренного действия обновления `rkn.list` через `nfqws-menu`.
- 🧰 **Дополнительные утилиты:** DPI Detector, TG WS Proxy Rust, KeenKit и awg-manager.
- 📊 **Состояние системы:** отображение модели, KeeneticOS, архитектуры Entware, обнаруженных компонентов и доступных версий.
- 🌍 **Язык интерфейса:** русский и английский.
- 🔢 **Цифровое управление:** пункты меню пронумерованы; список удаления формируется по обнаруженным компонентам.
- 💾 **Резервные копии:** текущий скрипт и изменяемые файлы по предусмотренным сценариям сохраняются перед заменой.
- 🔄 **Самообновление:** пункт `23` получает Xmenu из репозитория проекта, проверяет загруженный файл и только после этого заменяет установленный скрипт.

## 📋 Требования

- ✅ Роутер Keenetic / Netcraze с доступным shell.
- ✅ Установленный и работающий Entware в `/opt`.
- ✅ SSH-доступ с правами `root`.
- ✅ Рабочие `opkg` и интернет-доступ к репозиториям Entware.
- ✅ Доступ к GitHub для загрузки проекта и сторонних исходников.
- ✅ Достаточно свободного места в `/opt` для выбранных компонентов.

Xmenu написан на POSIX-совместимом `sh` и рассчитан на BusyBox `ash`. В зависимости от выбранного действия могут потребоваться `curl`, `libnghttp2`, `ca-certificates`, `wget` или другие утилиты Entware. Установщик ниже ставит пакеты, необходимые для загрузки самого Xmenu; дополнительные зависимости конкретных компонентов устанавливаются отдельно при необходимости.

## ⚡ Быстрая установка одной командой

> 🧑💻 Подключись к роутеру по SSH, вставь **одну команду целиком** и нажми Enter. Не запускай её из фоновой задачи: меню рассчитано на интерактивный терминал.

```sh
opkg update && opkg install curl libnghttp2 ca-certificates && curl -fLsS --retry 3 -o /tmp/xmenu-v1.0.sh https://raw.githubusercontent.com/rangerxxyy/Xmenu/main/xmenu-v1.0.sh && sh -n /tmp/xmenu-v1.0.sh && mkdir -p /opt/bin /opt/etc/xkeen-menu/backups && { [ ! -f /opt/bin/xmenu ] || cp -p /opt/bin/xmenu "/opt/etc/xkeen-menu/backups/xmenu-before-$(date +%Y%m%d-%H%M%S).sh"; } && cp /tmp/xmenu-v1.0.sh /opt/bin/xmenu && chmod 700 /opt/bin/xmenu && sh /opt/bin/xmenu
```

### ✅ Что делает команда

- 📦 Тихо обновляет индексы Entware и устанавливает инструменты HTTPS-загрузки.
- ⬇️ Скачивает файл во временный каталог, проверяет его размер, `sh`/BusyBox `ash`-синтаксис и наличие пункта `23`.
- 💾 Сохраняет старый скрипт в `/opt/etc/xkeen-menu/backups/`, затем устанавливает новую версию через временный файл.
- ▶️ Запускает `sh /opt/bin/xmenu` **без `exec`** — после выхода из меню управление возвращается в текущую интерактивную SSH-оболочку.

Если загрузка или проверка не проходит, существующий скрипт не заменяется.

### ▶️ Повторный запуск

После установки можно запустить меню из SSH:

```sh
/opt/bin/xmenu
```

Если `/opt/bin` добавлен в `PATH`, обычно достаточно команды `xmenu`.

## 🖥️ Информация об устройстве

### 📡 Модель и KeeneticOS

Xmenu запрашивает локальный Keenetic RCI API (`http://127.0.0.1:79/rci/show/version`). При отсутствии данных пробует резервные источники, включая `ndmc`, `/proc/device-tree/model` и `/proc/device-tree/compatible`.

### 🧠 Архитектура Entware

Архитектура определяется по `opkg print-architecture`, затем по `/opt/etc/opkg.conf`, и только затем по `uname -m`. Это архитектура Entware, которая важна для установки пакетов; она может отличаться от общего описания процессора.

### 📊 Установленные компоненты

Статус формируется по данным `opkg`, исполняемым файлам, init-скриптам и файлам версий. Набор компонентов зависит от конкретной установки. Если версия не определена, это не обязательно означает неисправность.

- 🖼️ **2 — XKeen UI zxc-rv** и **3 — XKeen UI umarcheh001:** устанавливают разные реализации интерфейса. Перед сменой UI проверь совместимость с текущим XKeen.

Автозагрузка и периодическое обновление GeoIPSet зависят от успешной установки компонентов и корректно работающего cron.

### 📦 Пункты 9–10 — комбинированные профили

Оба сценария объединяют ядро (Mihomo или Xray), GeoIPSet, XKeen Auto, XKeen UI, NFQWS2 и NFQWS Web. Если один шаг завершается ошибкой, изучи его вывод до повторного запуска всего профиля.

## 🎯 Стратегии NFQWS / NFQWS2

### 🎛️ Пункт 11 — выбор стратегии

Открывает список доступных стратегий. При применении Xmenu подготавливает конфигурацию, старается сохранить поддерживаемые параметры текущего файла, загружает необходимые ресурсы, делает резервную копию конфига и перезапускает соответствующую службу.

| Движок | Конфигурация | Init-скрипт (если установлен) |
|---|---|---|
| NFQWS v1 | `/opt/etc/nfqws/nfqws.conf` | `/opt/etc/init.d/S51nfqws` |
| NFQWS2 | `/opt/etc/nfqws2/nfqws2.conf` | `/opt/etc/init.d/S51nfqws2` |

### 🛡️ Пункт 12 — защита пользовательской стратегии

Проверка blobs/lists не должна безусловно заменять кастомную конфигурацию стандартной стратегией. Xmenu пытается отличить конфиг, который по-прежнему соответствует исходнику выбранной стратегии, от изменённого пользователем. Если конфиг кастомизирован, автоматическая подмена только из-за старой метки стратегии не должна выполняться. Для намеренной смены используй пункт `11`.

### 🔄 Если стратегия не заработала

- 🔎 Проверь, что выбрал правильный движок — NFQWS или NFQWS2.
- 📦 Убедись, что все blobs/lists на месте.
- 🔁 Проверь состояние соответствующей службы и init-скрипта.
- 💾 При необходимости восстанови предыдущую конфигурацию.

## 📦 Blobs, lists и rkn.list

### 🔍 Пункт 12 — blobs и lists активной стратегии

Xmenu находит ссылки на blobs (`.bin`) и списки (`.list`) в активном конфиге и проверяет наличие файлов. Если доступен манифест SHA-256, контрольная сумма может использоваться для проверки содержимого. Перед заменой существующих файлов предусмотренные сценарии пытаются создать резервную копию.

### 📥 Пункт 13 — необходимые blobs NFQWS2

Целевой каталог:

```text
/opt/etc/nfqws2/blobs
```

Команда загружает необходимые ресурсы из доступных источников и проверяет их в тех случаях, где проверка предусмотрена текущей реализацией.

### 🧾 Пункт 14 — `rkn.list`

Вызывает действие `update_rkn_list` из актуального `nfqws-menu`. Типичные пути списка:

| Движок | Путь |
|---|---|
| NFQWS v1 | `/opt/etc/nfqws/rkn.list` |
| NFQWS2 | `/opt/etc/nfqws2/lists/rkn.list` |

Наличие файла само по себе не означает, что стратегия использует его: проверь привязку через `MODE_LIST` или предусмотренный движком параметр hostlist.

## 🧰 Дополнительные утилиты

### 🔬 Пункт 15 — DPI Detector

Инструмент диагностики DPI/DNS. Используется проект [Runnin4ik/dpi-detector](https://github.com/Runnin4ik/dpi-detector), включая Rust-ветку. Совместимость зависит от архитектуры, ABI и доступных библиотек.

### 📡 Пункты 16–18 — дополнительные утилиты

- 📡 **16 — TG WS Proxy Rust:** вызывает предусмотренное действие установки/обслуживания. Не открывай веб-панели компонентов напрямую в WAN без защиты.
- 🧰 **17 — KeenKit:** запускает существующую установку или предлагает предусмотренный сценарий установки.
- 🛜 **18 — awg-manager:** вызывает соответствующее действие из upstream-меню `nfqws-menu`; до изменения AWG/WireGuard-конфигурации проверь назначение интерфейсов.

### 📊 Пункт 19 — статус и версии

Показывает сведения об устройстве и найденных компонентах. Источники версий могут различаться; версия из локального файла иногда является сохранённым значением.

### 🌍 Пункт 20 — RU / EN

Переключает язык интерфейса Xmenu. Язык сторонних установщиков не обязательно изменится. Настройка хранится в `/opt/etc/xkeen-menu/language`.

## 🗑️ Удаление компонентов

### 🧹 Пункт 21 — удалить компоненты

Подменю показывает обнаруженные компоненты и предлагает выбирать их только цифровыми номерами. Доступные действия зависят от установленных пакетов и файлов.

- 📦 NFQWS/NFQWS2 и UI.
- 🧩 XKeen и варианты XKeen UI.
- 🚀 Обнаруженные ядра Xray/Mihomo.

Удаление пакета не всегда означает удаление всех пользовательских конфигов. Перед подтверждением прочитай сообщение об операции.

### 🧨 Пункт 22 — удалить Xmenu

Удаляет `/opt/bin/xmenu` и связанные задания cron Xmenu. Отдельное подтверждение определяет, нужно ли удалить локальные данные и резервные копии. Пункт не предназначен для удаления XKeen, NFQWS2 или других сетевых компонентов.

## 🔄 Обновление Xmenu

### ⬇️ Пункт 23 — обновить с GitHub

Источник обновления:

[`xmenu-v1.0.sh` — RaNgeRwWs/Xmenu](https://raw.githubusercontent.com/RaNgeRwWs/Xmenu/main/xmenu-v1.0.sh)

Перед заменой скрипт проверяет несколько условий:

- 🔎 файл успешно загружен и не подозрительно мал;
- 🧾 заголовок и ключевые элементы скрипта присутствуют;
- 🧭 присутствует пункт меню `23` и его обработчик;
- 🧪 `sh -n` не находит синтаксических ошибок;
- 💾 текущая версия сохраняется в резервную копию;
- 🔁 новый файл перемещается на место установленного скрипта после проверок.

Если проверка не проходит, текущая версия должна остаться на месте. При успешном обновлении меню перезапускается. Для работы самообновления на GitHub должна быть опубликована версия, содержащая сам пункт `23`.

> ℹ️ Если в установленной версии пункта `23` нет, сначала обнови скрипт командой из раздела [Быстрая установка](#-быстрая-установка-одной-командой). Старая копия не может вызвать функцию, которой ещё нет в её коде.

## 🛡️ Безопасность и ответственность

### 🔐 Что следует знать

- 🔑 Некоторые действия скачивают и запускают сторонние установщики с правами `root`.
- 🌐 HTTPS защищает канал передачи, но не гарантирует безопасность загруженного кода.
- 🧪 `sh -n` проверяет синтаксис, но не является полным аудитом безопасности.

- 🔥 Изменение стратегий, маршрутизации и сетевых правил может повлиять на доступ к интернету или самому роутеру.

Перед публичным выпуском рекомендуется проверить на поддерживаемом устройстве:

- 🧯 Восстановление из резервной копии после намеренно прерванной операции.

## 🧯 Диагностика

### 🔌 SSH закрывается после запуска

Запускай установленный скрипт из интерактивной сессии:

```sh
sh /opt/bin/xmenu
```

Установочная команда использует `sh /opt/bin/xmenu` без `exec`. При запуске как одноразовой удалённой SSH-команды соединение может закрыться после завершения команды — это зависит от способа запуска и SSH-клиента.

### 🌐 Загрузка с GitHub не проходит

- 🔎 Проверь доступность `raw.githubusercontent.com` с роутера и системное время.
- 📦 Убедись, что установлены `curl` и сертификаты HTTPS.
- 🧾 Не заменяй рабочий скрипт пустым файлом или HTML-страницей ошибки.

### 🧩 Компонент не отображается

Проверь `opkg list-installed`, имя пакета, бинарные файлы и init-скрипты. Не у всех сторонних компонентов есть единый источник номера версии.

### 📝 Что приложить к Issue

Укажи модель роутера, версию KeeneticOS, вывод `opkg print-architecture`, номер пункта меню и полный текст ошибки. Перед публикацией логов удали пароли, токены, ключи, публичные IP и прочие чувствительные данные.
