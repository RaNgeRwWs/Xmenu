## 🚀 Быстрая установка

Подключитесь к роутеру через SSH под `root` и вставьте команду целиком. Она загрузит Xmenu из репозитория, проверит файл, сохранит старую версию и сразу откроет меню.

```sh
mkdir -p /opt/bin && curl -fsSL --retry 3 -o /tmp/xmenu.sh https://raw.githubusercontent.com/rangerxxyy/Xmenu/main/xmenu-v1.0.sh && sh -n /tmp/xmenu.sh && { [ ! -f /opt/bin/xmenu ] || cp -p /opt/bin/xmenu /opt/bin/xmenu.bak; } && cp /tmp/xmenu.sh /opt/bin/xmenu && chmod 700 /opt/bin/xmenu && sh /opt/bin/xmenu
```

Установщик не заменит действующий файл, если загрузка или проверка не пройдут. Меню запускается как дочерний процесс, без `exec`, поэтому после выхода из Xmenu интерактивная SSH-оболочка должна остаться доступной.

## ▶️ Открыть Xmenu

После установки обычно достаточно выполнить:

```sh
xmenu
```

Если команда не найдена, запустите скрипт по полному пути:

```sh
/opt/bin/xmenu
```

## 🗑️ Удалить Xmenu

1. Выполните `xmenu`.
2. Выберите пункт **22 — «Удалить Xmenu»**.
3. Прочитайте запросы и подтвердите удаление.

Удаление Xmenu не предназначено для удаления XKeen, NFQWS/NFQWS2 и других установленных сетевых компонентов. Следуйте подсказкам меню относительно кэша и резервных копий. Не удаляйте каталог `/opt/etc/xkeen-menu/` вручную, если хотите сохранить резервные файлы.

## 🔄 Обновить Xmenu

Откройте меню командой `xmenu` и выберите пункт **23 — «Обновить Xmenu с GitHub»**. Скрипт загружается из текущего репозитория:

`https://raw.githubusercontent.com/rangerxxyy/Xmenu/main/xmenu-v1.0.sh`

Перед заменой обновлятор проверяет файл и shell-синтаксис. При неудачной проверке установленная версия должна остаться на месте. Чтобы пункт `23` появился в старой версии, сначала установите текущий скрипт командой из раздела выше.

## О проекте

Xmenu — POSIX shell-скрипт для управления установкой и обслуживанием сетевых компонентов на роутерах Keenetic / Netcraze с Entware. Он объединяет вызовы установщиков, готовые профили XKeen, операции со стратегиями NFQWS/NFQWS2 и базовую диагностику.

Xmenu не является отдельным DPI-движком, VPN-протоколом или заменой KeeneticOS. Компоненты устанавливаются только после выбора соответствующего действия в меню.

## Требования

- Keenetic / Netcraze с доступным SSH-shell.
- Установленный Entware в `/opt` и рабочий `opkg`.
- Доступ к интернету и GitHub.
- Права `root` для установки и изменения системных файлов.
- Свободное место для выбранных пакетов и резервных копий.

Скрипт написан для POSIX `sh` и BusyBox `ash`. Дополнительные зависимости зависят от конкретного действия и стороннего компонента.

## Установка компонентов и профили

Пункты `1–6` запускают установщики отдельных компонентов. Пункты `7–10` предназначены для установки профилей XKeen Auto с Mihomo или Xray, GeoIPSet, XKeen UI и выбранными NFQWS-компонентами.

Перед запуском комбинированного профиля проверьте, какие компоненты уже установлены и какие конфигурации вы используете. Если установщик сообщил об ошибке, прочитайте его вывод перед повторным запуском.

## Стратегии NFQWS / NFQWS2

Пункт `11` открывает список стратегий и позволяет выбрать нужную. Применение стратегии может изменить конфигурацию и перезапустить соответствующую службу. Перед сменой стратегии сохраните важные настройки.

Основные пути конфигурации:

| Движок | Конфигурация |
|---|---|
| NFQWS v1 | `/opt/etc/nfqws/nfqws.conf` |
| NFQWS2 | `/opt/etc/nfqws2/nfqws2.conf` |

Пункт `12` проверяет blobs и списки, на которые ссылается активная конфигурация. Он не должен заменять пользовательский кастомный конфиг стандартной стратегией лишь из-за устаревшей метки. Если нужно перейти на другую стратегию намеренно, используйте пункт `11`.

Пункт `13` устанавливает необходимые blobs NFQWS2. Каталог blobs:

```text
/opt/etc/nfqws2/blobs/
```

Пункт `14` вызывает обновление `rkn.list` через `nfqws-menu`. Наличие файла списка само по себе не означает, что текущая стратегия его использует: проверьте, подключён ли список в конфигурации.

## Информация об устройстве

Модель роутера и версию KeeneticOS скрипт получает из локального Keenetic RCI API и использует резервные источники, если данные недоступны. Архитектура Entware определяется в первую очередь через `opkg print-architecture`, затем через `/opt/etc/opkg.conf` и `uname -m`.

Отображаемый список установленных компонентов формируется по данным пакетов, файлам, исполняемым файлам и доступным версиям. Для некоторых сторонних компонентов версия может быть неизвестна.

## Дополнительные утилиты

- **DPI Detector** — инструмент диагностики DPI/DNS; совместимость зависит от архитектуры и доступных библиотек.
- **TG WS Proxy Rust** — действие установки/обслуживания через предусмотренный upstream-источник.
- **KeenKit** — запуск найденной установки или вызов установщика.
- **awg-manager** — действие управления AWG Manager через `nfqws-menu`.

Доступность и интерфейс этих утилит зависят от состояния upstream-репозиториев и совместимости с устройством.

## Удаление компонентов

Пункт `21` показывает обнаруженные компоненты и даёт выбирать действия цифрами. Удаление пакетов может затронуть связанные службы; внимательно читайте подтверждение перед каждым действием. Пользовательские конфигурации и резервные файлы не следует удалять вручную, пока не ясно, что они больше не нужны.

## Безопасность и ответственность

Некоторые действия Xmenu загружают и запускают сторонние установщики с правами `root`, меняют конфигурации или перезапускают службы. Используйте только те источники, которым доверяете, и перед крупными изменениями сохраняйте рабочие конфигурации.

- HTTPS защищает канал передачи, но сам по себе не гарантирует безопасность скачанного кода.
- `sh -n` проверяет синтаксис, а не безопасность или правильность работы установщика.
- Перед изменением стратегии убедитесь, что можете восстановить прежний конфиг.
- Не открывайте веб-панели компонентов напрямую в интернет без аутентификации и правил firewall.

### Отказ от гарантий

Xmenu предоставляется «как есть», без гарантии бесперебойной работы или пригодности для конкретной цели. Пользователь самостоятельно отвечает за выбор действий, установку, настройку, обновление и удаление компонентов, а также за последствия изменений на своём устройстве. Перед использованием пользователь должен оценить риски и обеспечить возможность восстановления настроек.

Автор Xmenu не несёт ответственности за потерю конфигураций, перебои доступа к интернету, сбои устройств или сторонних служб, несовместимость пакетов, изменения внешних репозиториев или ущерб, связанный с использованием проекта либо невозможностью его использования, в пределах, допускаемых применимым законодательством. Сторонние компоненты принадлежат их авторам и регулируются собственными лицензиями и условиями.

## Диагностика

**Не загружается скрипт:** проверьте интернет, DNS, системное время роутера и доступ к `raw.githubusercontent.com`. Не заменяйте рабочий скрипт, если загрузился пустой файл или HTML-страница ошибки.

**Команда `xmenu` не найдена:** используйте полный путь `/opt/bin/xmenu`.

**Компонент не отображается:** проверьте пакет через `opkg list-installed`, наличие бинарного файла и init-скрипта. Не все компоненты предоставляют одинаковый способ определения версии.

**SSH-сессия закрывается:** запускайте Xmenu в интерактивной SSH-сессии командой `xmenu` или `sh /opt/bin/xmenu`, а не из одноразовой удалённой команды. Установщик запускает меню без `exec`, чтобы оно не заменяло текущую оболочку.

При сообщении о проблеме укажите модель роутера, версию KeeneticOS, вывод `opkg print-architecture`, номер пункта меню и текст ошибки. Удалите из логов пароли, токены и другие чувствительные данные.
