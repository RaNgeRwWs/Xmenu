## Что умеет Xmenu

| Раздел | Возможности |
| --- | --- |
| 📦 Компоненты | XKeen Stable, Xray, Mihomo, панели XKeen UI, NFQWS2 и веб-интерфейсы |
| 🧩 Стратегии | Каталог из 40 вариантов NFQWS2, контрольные суммы, кэш и резервное копирование |
| 🌐 DNS | Текущие DNS интернет-фильтров, DoT/DoH, привязки доменов и статические hosts |
| 🎙 Discord | Обработка голосовой UDP-сессии в NFQWS2, исключение из ускорения и интеграция с XKeen |
| 🛠 Обслуживание | Зеркала Entware, копии `opkg.conf`, Dropbear Fix, сжатие UPX и удаление компонентов |
| 🔎 Диагностика | DPI Detector, версии установленных компонентов и состояние сервисов |

Xmenu работает поверх Entware: выполняет пакетные команды, запускает установщики выбранных компонентов и управляет их конфигурациями. Основные действия доступны через меню и команды SSH.

## Быстрые сценарии

Выбери задачу и пройди по указанным пунктам. Например, **11 → 6 → 2** означает: главное меню → управление NFQWS2 → настройки DNS → добавить DoH.

| Хочу… | Куда перейти | Что получится |
| --- | --- | --- |
| Установить NFQWS2 | **4** | Пакет NFQWS2 и его штатные файлы |
| Сразу настроить XKeen с Mihomo | **7** | Ядро, геофайлы, расписание обновления и автозагрузка |
| Применить готовую стратегию | **11 → 1** | Проверенная конфигурация с копией предыдущей |
| Подготовить все fake-пакеты | **11 → 2** | Каталог blobs NFQWS2 |
| Проверить зависимости действующего конфига | **11 → 3** | Проверка blobs и списков текущей стратегии |
| Добавить защищённый DNS | **11 → 6 → 1 / 2** | Общий DoT или DoH либо сервер для указанного домена |
| Направить отдельный домен к другому DNS | **11 → 6 → 3** | Готовая доменная привязка; для собственного домена — добавление DoT/DoH с заполнением поля домена |
| Попробовать исправить обрыв голоса Discord | **11 → 9 → 2** или **S → 3 → 2** | Правила обработки UDP-сессии в NFQWS2 |
| Сменить зеркало Entware | **21 → 3** | Новый источник пакетов и копия прежнего opkg.conf |
| Сохранить opkg.conf | **21 → 4 → 1** | Отдельная резервная копия |
| Восстановить opkg.conf | **21 → 4 → 2** | Последняя копия, созданная Xmenu |
| Обновить списки доступных пакетов | **21 → 5** | Новые индексы Entware |
| Обновить Xmenu | **20** | Проверка загрузки и замена скрипта с резервной копией |
| Удалить отдельный компонент | **18** | Список действий удаления с подтверждениями |

> [!TIP]
> Перед экспериментами со стратегиями создай архив командой `xmenu backup`. Копии `opkg.conf` управляются отдельно через **21 → 4**.


## Установка

Нужны Keenetic или Netcraze, установленный Entware в `/opt`, SSH-доступ с правами `root` и `curl` либо `wget` с поддержкой HTTPS. Для сетевых компонентов также нужны соответствующие компоненты прошивки и модули Netfilter.

### Установить стабильный релиз

Подключись к Entware по SSH и выполни:

```sh
mkdir -p /opt/bin
curl -fL --retry 3 'https://github.com/rangerxxyy/Xmenu/releases/latest/download/xmenu-v1.0.sh' -o /tmp/xmenu.sh &&
sh -n /tmp/xmenu.sh &&
{ [ ! -f /opt/bin/xmenu ] || cp -p /opt/bin/xmenu "/opt/bin/xmenu.bak.$(date +%Y%m%d-%H%M%S)"; } &&
cp /tmp/xmenu.sh /opt/bin/.xmenu-new && chmod 700 /opt/bin/.xmenu-new &&
mv -f /opt/bin/.xmenu-new /opt/bin/xmenu && xmenu
```

Далее для запуска достаточно:

```sh
xmenu
```

```sh

```

## Управление nfqws2

Открывается пунктом **11**. Стратегии и синхронизация используют найденный активный конфиг с приоритетом NFQWS2. Для IPSet, rkn.list и обхода DNS при установленных v1/v2 доступен выбор версии или обеих сразу.

```text
1.  Выбрать и применить стратегию nfqws
2.  Установить все blobs nfqws2
3.  Скачать/проверить blobs и lists активной стратегии
4.  Скачать rkn.list (nfqws / nfqws2)
5.  Обход блокировки DoT/DoH
6.  Настройки текущих DNS-серверов
7.  Обновить Ipset Lists
8.  Смена текущих fake:blob
9.  Discord: включить/выключить фикс
10. Обновление hosts
0.  Назад
```

### 1. Выбрать и применить стратегию

Показывает каталог конфигураций для выбранной версии. Для NFQWS2 в выпуск включены **13 дополнительных конфигураций** к исходным 27 — всего **40 вариантов**, включая `configuration_3.2`, `hybrid_2.0` и `aggressive_hybrid`.

- В названиях меню убраны расширения `.conf` и числовые префиксы.
- Активная стратегия определяется сравнением с конфигом и выделяется бирюзовым.
- Манифест с контрольными суммами кэшируется на час; конфиги скачиваются по выбору.
- Для дополнительных стратегий манифест и конфиг берутся из одной ревизии репозитория.
- Перед заменой сохраняется резервная копия, проверяется SHA-256 и синтаксис конфигурации.
- После применения перезапускается соответствующий сервис; ошибка перезапуска выводится отдельно.

Проверенный локальный кэш используется при недоступности загрузки. Работоспособность конкретной стратегии зависит от провайдера, версии NFQWS и маршрута трафика.

1. Установи NFQWS2 через пункт **4**, если пакет ещё отсутствует.

6. Проверь нужные сайты и приложения из своей сети. Успешная проверка файла означает его целостность и корректный shell-синтаксис; результат обхода зависит от условий подключения.

Основной конфиг v1 — `/opt/etc/nfqws/nfqws.conf`; v2 — `/opt/etc/nfqws2/nfqws2.conf`. Доступность выбора определяется найденными конфигами или установленными пакетами в зависимости от операции.

<details>
<summary><b>Чем отличаются blobs, lists, IPSet и rkn.list</b></summary>

| Термин | Что хранится | Для чего нужен |
| --- | --- | --- |
| **Стратегия** | Shell-конфигурация `.conf` | Задаёт фильтры трафика, аргументы обработки, порты и пути к ресурсам |
| **Blob** | Бинарный файл `.bin` | Содержит данные fake-пакета или другого ресурса стратегии |
| **Hostlist / lists** | Текстовый список доменов | Ограничивает применение стратегии указанными именами |
| **IPSet list** | IP-адреса и сети CIDR | Выбирает трафик по адресам назначения |
| **rkn.list** | Отдельный доменный список | Подключается к конфигу как дополнительный hostlist |
| **hosts** | Пары `IP DOMAIN` | Создаёт статические DNS-привязки в прошивке роутера |

Пункт **11 → 2** загружает все доступные blobs NFQWS2. Пункт **11 → 3** работает с зависимостями активного конфига. **11 → 7** заменяет конкретный IPSet-список, а **11 → 10** управляет статическими DNS-привязками.

</details>


### 2. Установить все blobs NFQWS2

Скачивает каталог `.bin`-ресурсов в `/opt/etc/nfqws2/blobs`. Проверяет уже имеющиеся файлы и сверяет загруженные с контрольными суммами. В конце сообщает число обработанных файлов и ошибок.

**Когда использовать:** после первой установки NFQWS2 или перед проверкой нескольких стратегий, использующих разные fake-пакеты.

### 3. Проверить ресурсы активной стратегии

Разбирает пути к blobs и lists в действующем конфиге, проверяет наличие нужных файлов и загружает отсутствующие ресурсы. Обрабатывает зависимости текущего конфига, а не весь доступный каталог.

Если действующий конфиг совпадает с ранее выбранной и сохранённой в кэше стратегией, синхронизация также может обновить этот вариант из свежего каталога. При ручных изменениях, из-за которых конфиг перестал совпадать с кэшем, автоматическая замена стратегии пропускается; проверяются её ресурсы.

### 4. Скачать rkn.list

Обновляет доменный список для выбранного NFQWS, при необходимости добавляет ссылку на него в конфигурацию. Изменения сохраняются с резервной копией; сервис перезапускается, когда список или конфиг действительно изменились.

### 5. Обход блокировки DoT/DoH

Добавляет стратегию доступа к публичным защищённым DNS в `NFQWS_ARGS_CUSTOM`: для v1 используется классический desync, для v2 — Lua-стратегия. Проверяет наличие порта `853` в `TCP_PORTS` и `UDP_PORTS`, сохраняет конфиг и перезапускает выбранную службу.

Стратегия загружается отдельным файлом; при недоступности источника используется встроенный вариант. Ответ `n` отменяет действие **до загрузки, резервного копирования и записи**.

**Эта операция помогает получить доступ к DNS-сервисам.** Настройка самих DNS-серверов находится в следующем пункте.

### 6. Настройки текущих DNS-серверов

Открывает встроенное управление DNS Keenetic через `ndmc`. Подробное описание — [ниже](#настройки-dns-серверов).

### 7. Обновить IPSet Lists

Предлагает большой IP/CIDR-список Flowseal или стандартный список выбранного пакета. Можно обработать v1, v2 или обе версии.

| Версия | Файл |
| --- | --- |
| NFQWS v1 | `/opt/etc/nfqws/ipset.list` |
| NFQWS2 | `/opt/etc/nfqws2/lists/ipset.list` |

Перед записью удаляются комментарии и пустые строки, проверяется непустой результат и сохраняется резервная копия. После обновления перезапускается соответствующая служба. Большой список увеличивает объём обрабатываемых адресов и потребление ресурсов роутера.

### 8. Смена текущих fake:blob

Находит именованные `fake:blob=NAME` по секциям конфига и показывает файл, на который указывает `--blob=NAME:...`. Hex-значения пропускаются, повторяющиеся имена объединяются.

После выбора предлагает локальные `.bin`, файлы из манифеста или резервного каталога. Скачивает выбранный ресурс, переназначает путь `--blob`, проверяет shell-синтаксис и сохраняет конфигурацию с бэкапом. Перезапуск службы выполняется по подтверждению.

### 9. Discord Fix

Направляет UDP-пакеты голосовой сессии на портах **19294–19344** и **50000–50100** в NFQWS2 на протяжении звонка. При наличии цели `PPE` исключает эти потоки из ускорения прошивки. Учитывает интерфейсы, номер очереди и политики выбранной конфигурации NFQWS2, включая значения из `.run`.

```text
1. Статус / диагностика
2. Включить фикс
3. Выключить фикс
4. XKeen: исключить порты Discord   [если установлен XKeen]
0. Назад
```

При включении создаются собственные цепочки firewall, init-скрипт и хук восстановления правил. Выключение снимает правила Xmenu и удаляет файлы включения фикса. Пункт XKeen добавляет порты в `port_exclude.lst` и предлагает перезапуск работающего XKeen.

Фикс обеспечивает обработку сессии; подходящая стратегия Discord должна быть в конфигурации NFQWS2. После включения переподключись к голосовому каналу.

### 10. Обновление hosts

Загружает список статических DNS-привязок, разбитый на секции. Можно выбрать несколько секций через запятую, все записи, удалить домены из этого списка или посмотреть текущие привязки.

```text
1…N. Секции hosts-файла
  a. Все секции
 88. Удалить домены из этого hosts-файла
 99. Показать текущие записи
  0. Назад
```

Записи применяются командой `ip host DOMAIN IP`, удаляются через `no ip host DOMAIN`. Поддерживается IPv4; некорректные адреса и домены пропускаются, для каждого домена сохраняется один IP. Перед изменением создаётся копия текущих `ip host`, затем сохраняется конфигурация Keenetic. При выборе более 64 доменов показывается предупреждение о лимите роутера.

## Настройки DNS-серверов

**Путь: 11 → 6.** Экран показывает DNS интернет-фильтров, общие DoT/DoH и внешние DNS без шифрования без дублирующих технических секций.

```text
DNS-серверы Keenetic

Интернет-фильтры
Отдельные DNS-серверы фильтров не настроены.

Общие DNS: DoT 0/8 · DoH 1/8
DoH: https://dns.google/dns-query
Запросы к этим серверам передаются с шифрованием.

1. Добавить DoT
2. Добавить DoH
3. Привязать домен к DNS (пресеты)
4. Удалить общие DNS-серверы
0. Назад
```

| Действие | Что изменяет |
| --- | --- |
| **Добавить DoT** | Добавляет TLS-сервер с адресом, портом и SNI. Доступны пресеты и ручной ввод `99`. |
| **Добавить DoH** | Добавляет HTTPS URI DNS-сервера. Поддерживает пресеты и ручной ввод `99`. |
| **Привязать домен** | Настраивает выбранный DNS для определённых доменов: Instagram, Twitch, Supercell и других либо для собственного домена. |
| **Удалить общие DNS-серверы** | Показывает общие upstream-серверы для выборочного удаления. Записи интернет-фильтров исключены из этого списка. |

В пресетах есть Яндекс, Cloudflare, Google, Quad9, CleanBrowsing, OpenDNS, AdGuard, ControlD, DNS.SB, DNS4EU, Alibaba, DNSPod, Xbox-DNS, Comss, Malw Link, NullsProxy, Geo Hide, AstraCat, Bezmezhau, DNS-AI, Mafioznik и Shecan. Можно выбрать несколько номеров через запятую и указать домен, для которого применяются серверы.

Счётчики `DoT N/8` и `DoH N/8` относятся к общим серверам секции System. Профили фильтров и политики в них не учитываются.

<details>
<summary><b>Почему Keenetic возвращает 127.0.0.1 вместо адреса DNS?</b></summary>

При включении DoT/DoH роутер направляет запросы своему внутреннему защищённому DNS-прокси. В диагностике появляются адреса вида `127.0.0.1:40508`; они принадлежат локальному процессу роутера. Внешний сервер при этом остаётся выбранным DoT/DoH.

Xmenu скрывает такие служебные адреса из списка DNS без шифрования и показывает настоящий адрес DoT или URI DoH. Управление DNS выполняется системным `ndmc`, а изменения сохраняются в конфигурации прошивки.

</details>

## Сервисное меню

Нажми **S** в главном меню.

```text
1. Dropbear Fix
2. Сжать bin/sbin
3. Discord Fix
0. Назад
```

### Dropbear Fix

Переносит Entware Dropbear с порта `22` на `222` и исправляет PID-файл с `/opt/var/run` на `/var/run`. Сохраняет изменяемые файлы и проверяет результат перед перезапуском.

Есть два варианта: исправить порт и PID-файл или дополнительно сбросить пароль root Entware на `keenetic`. Сброс требует отдельного выбора и подтверждения. Перезапуск SSH выполняется в фоне и может разорвать текущую сессию; повторное подключение — на порт `222`.

### Сжать bin/sbin

Обрабатывает поддерживаемые исполняемые файлы в `/opt/bin` и `/opt/sbin` через UPX. Уже сжатые или неподдерживаемые файлы пропускаются. Для распаковки отдельного файла используется `upx -d ПУТЬ`.

### Discord Fix

Открывает то же управление голосовым UDP-трафиком, что **11 → 9**. Описание действий приведено в [разделе Discord Fix](#9-discord-fix).

## OPKG и зеркала Entware

Открывается пунктом **21**. Показывает текущий адрес репозитория, а при ручном выборе — регион и активное зеркало.

```text
1. Авто-выбор Entware
2. Проверить доступность зеркал Entware
3. Выбрать зеркало Entware вручную
4. Копии opkg.conf
5. Выполнить opkg update
0. Назад
```

| № | Действие | Результат |
| --- | --- | --- |
| 1 | **Авто-выбор** | Проверяет зеркала и выбирает доступный источник с лучшим измеренным откликом. |
| 2 | **Проверить доступность** | Показывает статус, регион, адрес и результаты загрузки индекса каждого зеркала. |
| 3 | **Выбрать вручную** | Открывает каталог зеркал с текущим выбором; смена источника сохраняет прежний конфиг. |
| 4 | **Копии opkg.conf** | Открывает создание, восстановление и удаление резервных копий. |
| 5 | **opkg update** | Обновляет локальные индексы доступных пакетов. Установленные пакеты эта команда не обновляет. |

Проверка скачивает и анализирует `Packages.gz`: HTML-страница блокировки, повреждённый архив или ответ без корректного индекса не считаются рабочим зеркалом. При сбое загрузки используется ограниченное число повторов и резервный загрузчик.

### Копии opkg.conf — пункт 21 → 4

```text
1. Создать копию opkg.conf
2. Восстановить копию opkg.conf
3. Удалить все копии opkg.conf
0. Назад
```

- **Создать** — сохраняет текущий `/opt/etc/opkg.conf` с датой и уникальным именем в `/opt/etc/xmenu/backups/`.
- **Восстановить** — выбирает последнюю сохранённую Xmenu копию; перед заменой сохраняет текущий конфиг и запрашивает подтверждение.
- **Удалить все копии** — перечисляет найденные резервные файлы `opkg.conf` и удаляет их после подтверждения. Рабочий `opkg.conf` и копии других конфигураций сохраняются.

После смены зеркала новый источник действует сразу. Чтобы перечитать индекс пакетов, запусти **21 → 5**.

```text
0.  Назад
```

| Группа | Что удаляется |
| --- | --- |
| **1–6** | Выбранный компонент через предусмотренный для него способ удаления; перед действием выводится подтверждение. |
| **7** | Обнаруженные пакеты NFQWS после подтверждения. |
| **8** | Файлы по маскам резервных копий в каталогах конфигураций. Список показывается до удаления. |
| **9** | `.bin`-файлы каталога blobs NFQWS2. |
| **10** | Сохранённые копии и архивы Xmenu. |
| **11** | Дополнительные обнаруженные компоненты: панели, awg-manager, TG WS Proxy Rust, KeenKit, NFQWS v1, NFQWS UI и Xray. |

Для архива важных конфигураций доступна команда `xmenu backup`. Пункт **19** удаляет сам Xmenu и предлагает выбрать, сохранять ли его резервные копии.

## Обновление Xmenu

- **U** в главном меню проверяет наличие новой версии и выводит результат.
- **20** загружает обновление Xmenu, проверяет файл и сохраняет установленную версию перед заменой.
- `xmenu update-xmenu` запускает эту же операцию напрямую.

Проверка обновлений выполняется независимо от `opkg update`. Наличие нового релиза не запускает замену файлов автоматически.

## Если что-то не работает

<details>
<summary><b>Не скачивается файл или недоступно зеркало</b></summary>

Проверь дату роутера, работу DNS и доступ по HTTPS. Попробуй GitHub Raw или зеркало из раздела установки. Для Entware открой **21 → 2**: Xmenu проверит именно индекс пакетов и покажет результат, а не только доступность адреса.

</details>

<details>
<summary><b>Компонент установлен, но не работает</b></summary>

Проверь требования компонента, архитектуру Entware (`opkg print-architecture`), свободное место (`df -h /opt`), его конфигурацию и журнал службы. Успешная установка пакета сама по себе не подтверждает работоспособность стратегии в сети провайдера.

</details>

<details>
<summary><b>После изменения DNS не открываются сайты</b></summary>

Проверь URI DoH или адрес, порт и SNI DoT. Посмотри DNS интернет-фильтров и общие серверы в **11 → 6**. Для удаления добавленного общего сервера используй пункт 4 этого экрана. Если доступ к публичным DNS блокируется провайдером, проверь стратегию обхода в **11 → 5**.

</details>

<details>
<summary><b>Discord теряет голосовое соединение</b></summary>

Открой **11 → 9 → 1**, проверь работающий NFQWS2, правила NFQUEUE/PPE и исключения XKeen. После включения фикса переподключись к голосовому каналу. При отсутствии подходящей стратегии в NFQWS2 один fullsession-фикс не обеспечивает обход блокировки.

</details>

При сообщении об ошибке укажи версию Xmenu, модель роутера, версию прошивки, архитектуру и точный пункт меню. Прикладывай полный вывод ошибки без паролей, токенов и приватных ключей.

## Проверка и восстановление

<details>
<summary><b>Полезные команды для проверки роутера</b></summary>

Сведения об устройстве и компонентах:

```sh
xmenu status
opkg print-architecture
df -h /opt
opkg list-installed
```

Состояние установленных служб:

```sh
/opt/etc/init.d/S51nfqws2 status
/opt/etc/init.d/S51nfqws status
/opt/etc/init.d/S52xmenu-discord-fullsession status
```

Запускай команду той службы, которая установлена на твоём устройстве. Проверка Discord Fix также доступна через **11 → 9 → 1**.

Текущий DNS и сохранённые статические привязки:

```sh
LD_LIBRARY_PATH=/lib:/usr/lib ndmc -c 'show dns-proxy'
LD_LIBRARY_PATH=/lib:/usr/lib ndmc -c 'show running-config' | grep '^ip host '
```

Маршруты и процессы:

```sh
ip route show default
ps | grep '[n]fqws'
```

</details>

<details>
<summary><b>Вернуть предыдущую конфигурацию NFQWS2</b></summary>

Найди копию, созданную перед неудачным изменением:

```sh
ls -lt /opt/etc/xmenu/backups/nfqws2.conf.*.bak
```

Скопируй нужный файл во временный путь, проверь его и сохрани текущую конфигурацию перед восстановлением:

```sh
cp /opt/etc/xmenu/backups/ИМЯ_КОПИИ.bak /tmp/nfqws2-restore.conf &&
sh -n /tmp/nfqws2-restore.conf &&
cp -p /opt/etc/nfqws2/nfqws2.conf "/opt/etc/nfqws2/nfqws2.conf.before-restore.$(date +%Y%m%d-%H%M%S).bak" &&
cp /tmp/nfqws2-restore.conf /opt/etc/nfqws2/.nfqws2-restore.conf &&
mv /opt/etc/nfqws2/.nfqws2-restore.conf /opt/etc/nfqws2/nfqws2.conf &&
/opt/etc/init.d/S51nfqws2 restart
```

Замени `ИМЯ_КОПИИ.bak` реальным именем из вывода `ls`. Для v1 используются его конфиг, каталог и init-скрипт. Восстановление `opkg.conf` удобнее выполнить через **21 → 4 → 2**.

</details>

<details>
<summary><b>Как проверить результат сервисных операций</b></summary>

| Операция | Где проверить |
| --- | --- |
| Смена зеркала | **21** — строка текущего репозитория; **21 → 5** — загрузка индексов |
| Создание копии opkg.conf | Выведенный путь копии и каталог `/opt/etc/xmenu/backups/` |
| Применение стратегии | **11 → 1** — активный вариант; `S51nfqws2 status` — состояние службы |
| Установка blobs | Итоговый счётчик файлов; повторная проверка через **11 → 3** |
| Добавление DNS | **11 → 6** — новый адрес DoT/URI DoH и изменившийся счётчик |
| Применение hosts | **11 → 10 → 99** — текущие записи `ip host` |
| Включение Discord Fix | **11 → 9 → 1** — конфиг, очередь, правила и доступность PPE |
| Dropbear Fix | Новое подключение к Entware SSH на порт `222`; журнал `/tmp/xmenu-dropbear-restart.log` |
| Обновление Xmenu | Версия в заголовке; при необходимости — сравнение файла с `SHA256SUMS` релиза |

</details>

## Для разработчиков

<details>
<summary><b>Структура репозитория</b></summary>

```text
Xmenu/
├─ xmenu-v1.0.sh                 основной скрипт
├─ SHA256SUMS                   контрольная сумма релизного скрипта
├─ README.md                    руководство пользователя
├─ CHANGELOG.md                 история изменений
├─ LICENSE                      лицензия MIT
├─ strategies/
│  └─ nfqws2/
│     ├─ *.conf                 дополнительные конфигурации
│     └─ SHA256SUMS             контрольные суммы конфигураций
├─ tests/                       регрессионные и PTY-сценарии
└─ .github/workflows/           автоматические проверки
```

Рабочие сборки, логи и промежуточные материалы не включаются в Git. Для текстовых конфигураций и shell-файлов используется LF.

</details>

<details>
<summary><b>Добавить или изменить дополнительную стратегию</b></summary>

1. Размести полный конфиг в `strategies/nfqws2/` с понятным именем, без порядкового префикса.
2. Используй переменные и аргументы, поддерживаемые целевой версией NFQWS2. Не включай личные адреса, ключи и секреты.
3. Укажи корректные пути ресурсов, затем проверь shell-синтаксис.
4. После любых изменений пересчитай манифест из корня репозитория:

```sh
for config in strategies/nfqws2/*.conf; do
    sh -n "$config" || exit 1
done
sha256sum strategies/nfqws2/*.conf > strategies/nfqws2/SHA256SUMS
sha256sum -c strategies/nfqws2/SHA256SUMS
```

5. Проверь конфигурацию на совместимом роутере. `sh -n` проверяет оболочку, но не все параметры установленного бинарника NFQWS2.

После изменения самого `xmenu-v1.0.sh` также обнови корневой манифест:

```sh
sha256sum xmenu-v1.0.sh > SHA256SUMS
```

</details>

Сценарии используют временные конфиги и подменённые внешние команды. Они проверяют логику Xmenu; доступность серверов и работу конкретной стратегии нужно проверять в своей сети.

</details>
