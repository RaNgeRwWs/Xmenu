# Xmenu 1.4.4

Новый раздел диагностики сайтов, DNS и VPS, отдельная установка NFQWS v1 и уточнённые результаты сетевых проверок. Ниже перечислены изменения относительно опубликованной версии **1.4.3**.

## Проверка сайта

- Ввод до пяти доменов, URL, IPv4 или IPv6. Формат определяется автоматически; доступны собственный порт и путь страницы.
- Для каждого сайта автоматически выполняются два прогона: через текущие правила роутера, затем принудительно напрямую через WAN.
- Проверяются получение адресов DNS, установка TCP-соединения, TLS с SNI и проверкой сертификата, HTTP GET и чтение начала ответа.
- Все адреса и переходы собраны в одной таблице: **сайт/IP · DNS · TCP · TLS · HTTP/ответ**. Измерения TCP сохраняют десятые доли миллисекунды.
- Обрабатываются до пяти перенаправлений, циклы, некорректный Location, переход с HTTPS на HTTP и обрыв ответа раньше объявленной длины.
- Итог показывает подтверждённый результат: например, **«Сайт открывается — HTTP 301 → HTTP 200»**, ошибку TLS или этап, на котором ответ не получен.
- При отказе обычного DNS используется контрольный DoH с запросами A и AAAA. Такой результат сопровождается сообщением о проблеме обычного DNS.
- Прямой режим проверяет WAN-маршрут и исходный адрес; если обход не подтверждён, обычный путь не выдаётся за прямой.

**Запуск:** меню **13 → Диагностика сайта** или `xmenu site-check https://example.com`. Для отдельного прямого прогона: `xmenu site-check --direct https://example.com`.

TCP в таблице — время установки соединения, не ping. При прозрачном прокси оно может быть меньше 1 мс. Успешный GET подтверждает ответ проверенного URL, но не загрузку всех видео, скриптов и ресурсов страницы браузером.

## Проверка DNS-серверов

- Выбор серверов до запуска: популярные, весь каталог, отдельные номера или свои IPv4/IPv6.
- Более 30 пресетов; ручные параметры UDP, DoT/SNI и DoH.
- Пресеты и пользовательские серверы используют общую последовательность проверок. DoH и DoT обращаются к адресу своего сервиса, а не принудительно к UDP-IP.
- Цветная таблица **провайдер · DoH · DoT · UDP · реальный UDP-резолвер · Spoofing**.
- Таймауты, SYN Drop, TLS Drop, ошибки сертификата и ответы DNS отображаются в ячейках.
- Проверки контрольных доменов, несуществующего имени, признаков Fake-IP и подозрительных ответов. Исходящий адрес UDP-резолвера сопоставляется с организацией, когда данные доступны.
- Исправлены измерения задержки, обработка пользовательского ввода и избыточная ширина столбца резолвера.

**Запуск:** меню **13 → Проверка DNS-серверов** или `xmenu dns-check`.

## Доступность VPS-сервера

- Принудительное подключение через WAN с проверкой маршрута, интерфейса и исходного адреса, в обход пользовательского перенаправления XKeen/NFQUEUE.
- ICMP разного размера, DF/MTU, TCP и SYN, основные порты 22/80/443/8080/8443 и дополнительные пробы при неоднозначном результате.
- UDP/443 с проверкой ответа QUIC, DNS/53, NTP/123 и STUN. Молчание UDP не считается доказательством бана IP.
- Отдельный SSH/22, HTTP, TLS 1.2/1.3 и HTTPS. Ответ SSH подтверждает работу протокола; авторизация не выполняется.
- Три трассировки: ICMP, UDP и TCP/443, максимум 15 переходов. Промежуточные узлы отделены от конечного VPS.
- Внешнее сравнение ICMP, TCP/443 и TCP/22 через Check-Host с резервным Globalping. Сопоставляются одинаковые IP и порты; ошибки API не становятся ошибками VPS.
- Поиск ранее замеченных портов InternetDB с последующей живой проверкой, ASN/BGP-префикс, видимость маршрута и RPKI. Исторические данные не выдаются за текущую доступность.
- Проверка возможных локальных запретов firewall без изменения постоянных правил.
- Итог отдельно сообщает доступность IP и неопределённость причины молчания отдельных портов. Нет выдуманного процента достоверности или заявления о бане на основании одного таймаута.
- Удалены кнопка D, дополнительные экраны логов и сохранение результатов в файлы. Время проверки подписано отдельно.

**Запуск:** меню **13 → Доступность VPS-сервера** или `xmenu server-check IP`. Внешние проверки включены по умолчанию; для отдельного локального запуска по SSH доступен `--no-external`.

Временные исключения ограничены проверяемыми потоками и удаляются после завершения или отмены. Службы XKeen/NFQWS не останавливаются. Внешним проверочным сервисам передаётся проверяемый IP. Ошибка сертификата для голого IP сама по себе не означает блокировку.

## Отдельная установка NFQWS v1

В разделе установки добавлен самостоятельный **пункт 5 — nfqws v1**. NFQWS2 остаётся пунктом 4.

Установка проходит по этапам:

1. Проверка архитектуры, OPKG и конфликтующих пакетов.
2. Подготовка зависимостей и HTTPS-загрузчика после подтверждения.
3. Резервное копирование существующих файлов и подключение официального репозитория.
4. Установка либо обновление `nfqws-keenetic`.
5. Проверка синтаксиса конфига и состояния службы.

При установленном `nfqws2-keenetic` или `tpws-keenetic` операция прекращается до изменений: пакеты конфликтуют. Автоматического удаления NFQWS2 нет. Команда SSH: `xmenu install-nfqws`.

## Интерфейс и надёжность

- В выборе стратегий добавлен пункт **99 — Дополнительные конфигурации**, отдельный каталог из **30 файлов `.conf`**. Основной список из 40 вариантов сохранён. В новом каталоге присутствуют переработанные версии некоторых основных конфигураций.
- Новые файлы находятся в `strategies/nfqws2/additional/`; загрузка по выбору, SHA-256, привязка к ревизии, кэш, подготовка ресурсов, бэкап и применение работают общей логикой. В названиях выбора нет `.conf`, префиксов 31/32 и NEW-01.
- В 43 локальных конфигурациях исправлены кавычки, необъявленные blobs, одиночные позиции разделения, порядок MODE и разорванные ветки circular. Удалены комментарии, пояснения, неподдерживаемые параметры и SYN-правила, которые не могли выполняться в ограниченном TLS-профиле. Проверены dry-run и загрузка Lua установленным NFQWS2 без перехвата трафика.
- Модель роутера — обычный белый; прошивка и версии утилит — яркий бирюзовый; архитектура в скобках — зелёная.
- После добавления v1 главное меню перенумеровано: **12 — управление NFQWS2, 13 — диагностика, 19 — удаление компонентов, 21 — обновление Xmenu, 22 — OPKG**.
- Исправлена резервная загрузка на системах без `timeout`: при установленном Python ограничивается время команды и завершается вся группа её дочерних процессов.
- README дополнен маршрутами меню, командами, описанием диагностик и их ограничений.
- Добавлены проверки протоколов, сетевых ответов, отмены, установщика v1, интерактивного ввода и запуска меню; контрольные суммы обновлены.

## Обновление

В установленном Xmenu выберите **«Обновить Xmenu»** либо выполните:

```sh
xmenu update-xmenu
```

Файлы релиза: **xmenu-v1.0.sh**, **SHA256SUMS**, **LICENSE**. Инструкция первой установки находится в начале README.

Расширенные диагностики требуют **Python 3 с ssl и доверенных сертификатов**. Без Python обычная проверка сайта использует базовый curl HEAD; прямой режим требует Python. Новая диагностика не меняет выбранные стратегии и DNS-серверы роутера.
