# Xmenu — дополнение к истории изменений

Сводка изменений для Xmenu v1.3.0 и последующих исправлений.

## ⚙️ 1. Фоновое обновление статуса компонентов

- **Устранена гонка при регистрации PID фонового процесса.** Исправлен порядок запуска фонового обновления: вспомогательный процесс записывает собственный PID в файл блокировки до запуска обновления статуса. Это предотвращает ситуацию, при которой быстро завершившийся воркер не успевал снять блокировку.
- **Улучшено управление блокировкой обновления.** Удаление блокировки привязано к PID родительского процесса, который запустил обновление. Это снижает риск зависания фонового механизма и конфликтов между несколькими экземплярами Xmenu.
- **Исправлен запуск из нестандартного пути.** Фоновый процесс больше не зависит исключительно от `/opt/bin/xmenu`. Xmenu пытается определить путь к текущему исполняемому скрипту, что улучшает совместимость с запуском из других расположений.
- **Улучшена очистка при завершении.** При штатном завершении Xmenu проверяет принадлежность блокировки текущему процессу, останавливает принадлежащий ему воркер и удаляет служебные файлы блокировки.
- **Исправлены PID-зависимые временные пути.** Восстановлена корректная подстановка PID в именах временных файлов проверки обновлений, что помогает избегать конфликтов и оставшихся временных файлов.

## 2. Улучшена загрузка через wget

- **Исправлена работа на минимальных сборках KeeneticOS.** Если системная утилита `timeout` и апплет `busybox timeout` недоступны, Xmenu больше не отказывается выполнять загрузку только по этой причине.
- **Добавлен резервный путь выполнения wget.** При отсутствии внешнего ограничения времени функция вызывает `wget` напрямую, используя переданные параметры сетевого тайм-аута `-T` и одной попытки `-t 1`.
- **Сохранена совместимость с существующим механизмом загрузки.** Если доступен `timeout`, используется штатный ограниченный запуск. Резервный вариант предназначен для систем, в которых отсутствуют оба варианта этой утилиты.

## 🛡️ 3. Безопасное удаление Xmenu и защита резервных копий

- **Добавлено подтверждение сохранения резервных копий.** При удалении Xmenu появляется отдельный вопрос о сохранении архивов конфигураций в `/opt/etc/xkeen-menu/backups`.
- **Сохранение бэкапов выбрано по умолчанию.** Пустой ввод или подтверждение сохраняют архивы конфигураций, включая ранее созданные резервные копии настроек.
- **Удаление архивов требует отдельного подтверждения.** Если пользователь отказывается от сохранения, Xmenu дополнительно уточняет, действительно ли нужно удалить все резервные копии.
- **Служебные файлы очищаются отдельно от пользовательских архивов.** При сохранении бэкапов удаляются манифесты, кэш, временные маркеры и остальные служебные файлы Xmenu, а каталог резервных копий остаётся.
- **Сохранено разделение Xmenu и установленных компонентов.** Удаление меню не выполняет автоматическую деинсталляцию XKeen, NFQWS2, Xray или Mihomo.

## ⚡ 4. Оптимизация производительности меню

- **Сокращено количество запускаемых процессов `awk`.** В функции `menu_item()` добавлена быстрая проверка длины текста средствами shell.
- **Ускорена отрисовка коротких пунктов.** Если название пункта помещается в допустимую ширину строки, оно выводится напрямую через `printf`, без создания дополнительного процесса.
- **Сохранён перенос длинных названий.** Для пунктов, которые не помещаются в доступную ширину терминала, продолжает использоваться существующая логика переноса строк.
- **Уменьшена лишняя нагрузка при открытии и перерисовке меню.** Оптимизация особенно актуальна для роутеров с ограниченными ресурсами процессора, где частые запуски внешних утилит могут замедлять интерфейс.

## 📦 5. Улучшена первоначальная установка Xmenu

- **Предотвращена лишняя перезапись установленного скрипта.** Перед копированием в `/opt/bin/xmenu` Xmenu сравнивает исходный и целевой файлы с помощью `cmp -s`.
- **Идентичная версия не устанавливается повторно.** Если содержимое файлов совпадает, операция завершается без повторного копирования и сообщения об установке.
- **Сохранена проверка перед активацией копии.** Если файлы различаются, продолжают выполняться копирование во временный файл, проверка синтаксиса через `sh -n` и установка проверенной копии.

## 🔧 6. Исправлена обработка необязательного rkn.list в пользовательских стратегиях

- **Устранена лишняя зависимость от rkn.list.** При проверке ресурсов Xmenu больше не считает отсутствующий `rkn.list` обязательным файлом для каждой пользовательской стратегии.
- **Удаляется только устаревшая ссылка на отсутствующий список.** Если конфигурация ссылается на `/opt/etc/nfqws2/lists/rkn.list` или `/opt/etc/nfqws/rkn.list`, а самого файла нет, Xmenu удаляет соответствующий аргумент `--hostlist`, не меняя остальные параметры стратегии.
- **Живая конфигурация резервируется до изменения.** Перед удалением ссылки из активного конфига создаётся резервная копия. При работе с временной копией выбранной стратегии изменение остаётся частью её подготовки.
- **Ссылка не добавляется обратно при смене стратегии.** Xmenu сохраняет использование RKN только тогда, когда соответствующий файл списка существует.
- **Остальные списки проверяются как раньше.** Это исключение касается только отсутствующего `rkn.list`; другие списки, на которые действительно ссылается конфигурация, продолжают проверяться и загружаться по прежним правилам.

> **Примечание:** если `rkn.list` отсутствует, правила фильтрации по этому списку не применяются. Чтобы использовать его снова, скачайте список через пункт **14** главного меню. Проверка не отключает и не удаляет другие списки или blobs.
